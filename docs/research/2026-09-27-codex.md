## Codex plugin and marketplace formats: reference (researched 2026-09-27)

Key finding: Codex does read Claude Code's formats. I confirmed this three ways: the docs, the source code, and a live probe on local codex-cli 0.157.1.

### 1. Marketplace file

**Locations, checked in this order** [src, `codex-rs/core-plugins/src/marketplace.rs`, `MARKETPLACE_MANIFEST_RELATIVE_PATHS`]:
1. `.agents/plugins/marketplace.json`
2. `.agents/plugins/api_marketplace.json`
3. `.claude-plugin/marketplace.json`
4. `.cursor-plugin/marketplace.json`

The first file found under a root wins.

The docs name these locations [doc]:
- Repo: `$REPO_ROOT/.agents/plugins/marketplace.json`
- Personal: `~/.agents/plugins/marketplace.json`
- "Legacy-compatible": `$REPO_ROOT/.claude-plugin/marketplace.json`

The "marketplace root" is the directory above the layout. For example, the root of `X/.claude-plugin/marketplace.json` is `X`. `source.path` resolves against that root, not against `.agents/plugins/` [src][doc].

**Top-level fields** (`RawMarketplaceManifest`, camelCase, unknown fields ignored) [src]:
- `name` (string, **required**). It must match `[A-Za-z0-9_-]+`; dots are not allowed (`validate_plugin_segment(..., "marketplace name")`, `core-plugin-common/src/plugin_id.rs`).
- `interface` (optional object). Its only field is `displayName`.
- `plugins` (array, **required**).
- Claude's `owner` and `metadata` are ignored silently [probe].

**Plugin entry fields** (`RawMarketplaceManifestPlugin`) [src]:
- `name` (string, **required**).
  - Allowed characters are `[A-Za-z0-9._-]`, and dots may only separate non-empty segments.
  - At install time it must equal the plugin manifest's `name`, or you get the error "plugin.json name `X` does not match marketplace plugin name `Y`" (`core-plugins/src/store.rs`).
- `source` (**required**). Variants are listed below.
- `policy` (optional object; each field has a default):
  - `installation`: `"AVAILABLE"` (default) | `"INSTALLED_BY_DEFAULT"` | `"NOT_AVAILABLE"`.
  - `authentication`: `"ON_INSTALL"` (default) | `"ON_USE"`. The docs only say "on install or first use"; the literal `ON_USE` comes from the source.
  - `products`: optional array, e.g. `["CODEX"]` in openai-curated. An empty array means installable nowhere. A present array restricts which products can install it.
- `category` (optional string). It overrides the plugin manifest's `interface.category` ("Marketplace taxonomy wins").
- All other keys are flattened into `manifest_fields` and used as a **fallback manifest**:
  - This happens when the plugin dir has no manifest, or always for git/npm sources in listings.
  - Mapped fields: `displayName` → `interface.displayName`, `author.name` → `interface.developerName`, `homepage` → `interface.websiteUrl`, plus `version`, `description`, `keywords` and an `interface` object.
  - So Claude-style `"strict": false` entries work [src][probe].
- Docs rule [doc]: "Always include `policy.installation`, `policy.authentication`, and `category` on each plugin entry." The parser does not enforce this: they default [src], and my probe listed entries without them as `AVAILABLE`/`ON_INSTALL`.

**Source variants** (`RawMarketplaceManifestPluginSource`: untagged string or object tagged by `"source"`) [src][doc]:
- **Plain string**: `"./plugins/foo"`, treated as local.
- **`{"source":"local","path":"./..."}`**:
  - The path must start with `./` (the one exception is `.cursor-plugin/marketplace.json`).
  - It must use only normal path parts, so no `..`, and must stay inside the root.
  - `"."` or `"./"` means the marketplace root itself.
- **`{"source":"url","url":...,"path"?,"ref"?,"sha"?}`**: a Git repo; the plugin is at the repo root, or at `path` if given.
- **`{"source":"git-subdir","url":...,"path":...,"ref"?,"sha"?}`**: `path` is required.
- **Accepted `url` forms**: `http(s)://` (GitHub URLs get `.git` appended), `./` or `../` relative to the marketplace root (must stay inside it), `file://`, absolute `/...`, `ssh://`, `git@host:...`, or `owner/repo` shorthand.
- **`{"source":"npm","package":...,"version"?,"registry"?}`**:
  - `package` is required, and scoped names are allowed.
  - `version` accepts versions, dist-tags and ranges, but no `/`, `\` or `:`.
  - `registry` must be HTTPS, with no credentials, query or fragment.
  - The docs say lifecycle scripts are not run and the `npm` CLI must be installed.
- **Any other shape, such as Claude's `{"source":"github","repo":...}`**, is `Unsupported`, and that entry is **skipped with a warning** [src][probe].
- **Failure behaviour**: an entry that fails to resolve (e.g. a path without `./`) is skipped, not fatal [src][probe][doc]. Invalid JSON, or a missing `name`/`plugins`, fails the whole marketplace file.

### 2. Plugin manifest

Codex now has **two formats**. Detection is in `utils/plugins/src/plugin_namespace.rs::find_plugin_manifest_path` [src]:

**A. Portable "Agent Plugins" manifest: root `plugin.json`** (recommended for new packages [doc])
- It is used only if root `plugin.json` is a regular file (not a symlink) whose `$schema` starts with `https://agent-plugins.org/schemas/`.
- The only supported value is `https://agent-plugins.org/schemas/1.0.0/plugin.schema.json`.
- Root fields allowed (`AGENT_PLUGIN_FIELDS`, `core-plugins/src/agent_plugin_manifest.rs`): `$schema`, `name`, `version`, `description`, `author` {`name`,`email`,`url`}, `homepage`, `repository`, `license`, `keywords`, `extensions`. Other fields are dropped with a warning. A JSON `null` for any optional field is an error.
- **Required**: `$schema` and `name`.
  - `name` must be lowercase `[a-z0-9.-]`, at most 64 characters, start and end alphanumeric, with no `--` or `..`.
- **Components come from fixed paths**:
  - Skills are always in `./skills`; MCP servers are always in `./mcp.json` (no dot, Agent Plugins MCP schema `https://agent-plugins.org/schemas/1.0.0/mcp.schema.json`, and each server needs a transport `type`).
  - A `skills` or `mcpServers` declaration cannot change these [doc][src].
  - `.app.json` apps are **not loaded** for this format (`load_plugin_apps` returns empty) [src].
- **Derived interface defaults**: `displayName` = `name`; `short/longDescription` = `description`; `developerName` = `author.name`; `category` = `"Other"`; `websiteURL` = `homepage` [src].
- **OpenAI overlay**: `extensions["com.openai"]` holds `apps`, `hooks`, `interface`, and `onboardingSkill` (undocumented; `./` is optional).
  - If that object is present, it **replaces** `.codex-plugin/plugin.json` as the overlay. The two are not merged.
  - If it is absent, `.codex-plugin/plugin.json` supplies the overlay [doc][src].

**B. Legacy/compat manifest**. The first existing file wins, in this order (`DISCOVERABLE_PLUGIN_MANIFEST_PATHS`, `exec-server-protocol/src/protocol.rs`):
1. `.codex-plugin/plugin.json`
2. `.claude-plugin/plugin.json`
3. `.cursor-plugin/plugin.json`

Fields (`RawPluginManifest`, `core-plugins/src/manifest.rs`; all optional, unknown fields ignored):
- `name`: if empty it defaults to the plugin directory name.
- `version`, `description`, `keywords`.
- `skills`: string or string[].
- `mcpServers`: a path string or an inline object.
- `apps`: path string.
- `hooks`: a path, a path[], an inline hooks object, or an array of inline objects.
- `interface`: see below.
- `extensions`.
- `commands` is read separately (see section 4).

Defaults when a field is absent [src, `loader.rs`]:
- skills: `./skills` if it exists.
- MCP: `.mcp.json`.
- apps: `.app.json`.
- hooks: `hooks/hooks.json`.

An explicit `hooks` value replaces the default file; it does not add to it [doc].

**`interface` fields** (`RawPluginManifestInterface`, camelCase) [src]. Every field listed in the brief exists:
- `displayName`, `shortDescription`, `longDescription`, `developerName`, `category`.
- `capabilities`: string[].
- `websiteURL`, `privacyPolicyURL`, `termsOfServiceURL`: the serde field names are `websiteUrl` etc., with `...URL` accepted as aliases.
- `defaultPrompt`: a string or string[]. Whitespace is collapsed, at most 3 are kept, and any over 128 characters is dropped with a warning.
- `brandColor`.
- `composerIcon`, `logo`, `screenshots` (string[]): paths.
- Not in the docs' list: `logoDark` (parsed [src], and used by Figma). The submission docs also mention `brandColorDark` and `supportURL`, but the Codex runtime parser does not read them.

**Path rules** [src `resolve_manifest_path`][doc]:
- Paths must start with `./` and cannot be `./` alone.
- No `..`, no absolute paths, and they must stay inside the plugin root.
- A path that breaks these rules is **ignored with a warning**, not treated as an error.
- Store assets under `./assets/` [doc].
- In the portable layout, only `plugin.json` goes inside `.codex-plugin/`; hooks, `.app.json`, etc. stay at the plugin root [doc].

**Hooks**:
- Commands get `PLUGIN_ROOT` and `PLUGIN_DATA`, plus `CLAUDE_PLUGIN_ROOT` and `CLAUDE_PLUGIN_DATA` for compatibility [doc][src, `hooks/src/engine/discovery.rs:265-270`].
- Plugin hooks are untrusted until the user reviews them [doc].
- Codex does not run prompt or agent hook handlers [doc, submit-claude-plugin].

**Plugin-scoped MCP config**:
- In `config.toml`: `[plugins."<plugin>".mcp_servers.<server>]`, with keys `enabled`, `default_tools_approval_mode`, `enabled_tools`, `disabled_tools`, and `tools.<tool>.approval_mode` [doc].
- A relative `cwd` for a stdio server resolves against the plugin root [src].
- Transport `type` accepts `http`, `streamable_http`, `streamable-http`, `stdio` [src].
- Claude camelCase OAuth keys (`clientId`, `callbackPort`, …) are normalized [src].
- I found no `${CLAUDE_PLUGIN_ROOT}` expansion in `codex-mcp/src/plugin_config.rs` [inferred: Claude `.mcp.json` args using that placeholder may not resolve; not verified at runtime].

### 3. Discovery, install, cache, updates

**Discovery** [src `list_marketplaces_with_home`]:
- `$HOME` (personal) is checked first.
- Then configured/additional roots: the path itself, then the root dir, then the enclosing git repo root.

**Configured marketplaces** are the `[marketplaces.<name>]` table in `config.toml`:
- Keys: `source_type` (`"local"` or `"git"`), `source`, `ref`, `sparse_paths` [src][doc config-reference].
- They can come from system, cloud-managed, user, or trusted-project config.
- Git marketplaces are cloned into `$CODEX_HOME/.tmp/marketplaces/<name>` [src, `installed_marketplaces.rs`].
- `codex plugin marketplace add` writes the entry to user `config.toml` [src][probe].

**Repo marketplace in the CLI** [probe]:
- In a fresh git repo with an isolated `CODEX_HOME`, `codex plugin marketplace list` printed "No plugin marketplaces in scope." This happened with both `.agents/plugins/marketplace.json` and `.claude-plugin/marketplace.json`.
- The docs describe repo marketplaces mainly for the ChatGPT desktop app.
- [inferred] The CLI may need project trust, or not scan the cwd at all. Treat repo auto-discovery in the CLI as unconfirmed.

**CLI** (`codex plugin --help`, 0.157.1) [probe]:
- `add <PLUGIN[@MARKETPLACE]> [-m MARKETPLACE] [--json]`
- `list [-m] [--json] [--available]`
- `remove <PLUGIN[@MARKETPLACE]> [-m] [--json]`: "Uninstall a plugin and remove its local cache".
- `marketplace add <SOURCE> [--ref REF] [--sparse PATH]... [--json]`. SOURCE can be a local path, `owner/repo[@ref]`, an HTTPS Git URL, or an SSH Git URL. `--sparse` works only for Git sources [doc].
- `marketplace list [--json]`: "List plugin marketplaces Codex is currently considering and their roots".
- `marketplace upgrade [NAME] [--json]`: "Refresh configured Git marketplace snapshots"; with no NAME it upgrades all.
- `marketplace remove <NAME> [--json]`.
- The TUI has `/plugins`: marketplace tabs, install/uninstall, and Space to toggle a plugin on or off [doc learn].

**Enable/disable**: `[plugins."name@marketplace"] enabled = true|false` in user or trusted-project `.codex/config.toml` [doc]. A marketplace refresh may still install or refresh files for plugins set to `enabled = false` [doc].

**Cache**:
- Location: `$CODEX_HOME/plugins/cache/<marketplace>/<plugin>/<version>/`. Plugin data goes under `$CODEX_HOME/plugins/data/` [src][doc].
- Codex loads the cached copy, not the source [doc].
- **Which `<version>` is used** [src, `store.rs`, `manager.rs`]:
  - The manifest's `version` if it is set. Allowed characters are `[A-Za-z0-9._+-]`; a portable-format version with other characters gets a hashed `agent-plugins-<hex>` directory name instead.
  - Otherwise `"local"` for the legacy format, or `"1.0.0"` for the portable format.
  - For the OpenAI curated marketplace, a prefix of the git SHA.
  - **The docs say local plugins use `$VERSION` = `local`; that is only true when the manifest has no `version`** [src vs doc].
- **Updates**: installs are copied into place atomically, older version directories are removed, and the highest semver is the active one [src]. After editing a local plugin, re-install and restart so the cached copy updates [doc].

### 4. Claude Code interop

**Documented** [doc]:
- `.claude-plugin/marketplace.json` is a "legacy-compatible" repo marketplace.
- "OpenAI also accepts legacy and Claude-compatible manifests."
- Hooks get `CLAUDE_PLUGIN_ROOT` and `CLAUDE_PLUGIN_DATA`.
- For public submission, the portal converts `.claude-plugin/plugin.json` into `.codex-plugin/plugin.json` (`claude_format_normalized`).
- Not supported [doc, submit-claude-plugin]: `commands`, `agents`, `userConfig`/`${user_config.*}`, `outputStyles`, `lspServers`, `channels`, `dependencies`, and prompt/agent hook handlers. Commands and agents should be converted to skills.

**In the source** [src]:
- `.claude-plugin/plugin.json` is the second manifest location, read with the legacy parser.
- Legacy plugins get automatic **command migration**: `commands/`, or the manifest's `commands` paths, are converted to skills in `.codex-plugin/migrated-command-skills/` (`core-plugins/src/command_migration*.rs`).
  - A command is skipped unless its frontmatter has a non-empty `description`.
  - Each migrated skill is capped at 4,000 bytes.
- Claude-only manifest fields such as `author`, `license` and `agents` are ignored by the legacy parser.

**Verified live** [probe]. I added a Claude-format repo with `CODEX_HOME=<scratch>` and ran `marketplace add` then `plugin list --available --json`. Results:
- `owner`/`metadata` were ignored.
- The `"source":"./plugins/alpha"` entry, which has `.claude-plugin/plugin.json` with `version` 1.2.3, was listed with version 1.2.3.
- The `strict:false` entry with no manifest and `"version":"0.2.0"` was listed using the entry's own fields.
- The `{"source":"github","repo":...}` entry was **dropped**.
- The `"plugins/alpha"` entry (no `./`) was **dropped**.

**Practical rules for one repo serving both tools** [inferred from the above]:
- Use `./`-prefixed local sources, or `url`/`git-subdir` rather than Claude's `github` source.
- Marketplace `name` cannot contain dots.
- Plugin names should also meet the Agent Plugins rule (lowercase) if you later move to the portable format.

### 5. Validation and gotchas

- **There is no local `validate` command** in codex-cli 0.157.1 [probe]. The practical local checks are `codex plugin marketplace add <path>` (it calls `validate_marketplace_root`) plus `codex plugin list --available --json`.
  - Skipped entries only appear as `tracing` warnings, so compare the listed plugins against what you expect.
- **Portal validation** (https://developers.openai.com/plugins/deploy/submission-errors.md) is stricter than the runtime:
  - Required: `name`, a semver `version` (at most 64 characters), `description` (at most 1,024 characters), `author.name`, and `interface.displayName`, `shortDescription`, `longDescription`, `developerName`.
  - `author.name` must equal `interface.developerName`.
  - `name` pattern: ASCII letters, digits, `_`, `-`, at most 64 characters.
  - Directory limits: displayName at most 30 characters, shortDescription at most 30, longDescription at most 4,000, developerName at most 80, defaultPrompt at most 3 prompts of at most 128 characters each. Package validation allows 80 / 240 / 120 / 512.
  - `brandColor`: `#RRGGBB` with at least 2:1 contrast against white.
  - All URLs must be HTTPS.
  - `category` must be one of: Productivity, Creativity, Developer Tools, Business & Operations, Data & Analytics, Communication, Education & Research, Security, Finance, Healthcare, Travel, Entertainment, Other.
  - `capabilities`: at most 20 entries, each at most 120 characters.
  - Screenshots only with MCP custom UI: 706px wide.
  - In the compat layout, `skills`, `apps` and `mcpServers` must point to the root `skills/`, `.app.json` and `.mcp.json`.
  - A new release must change `version`.
- **Other gotchas**:
  - Don't just rename `.mcp.json` to `mcp.json`: the portable format needs a transport `type` on each server [doc].
  - `@plugin-creator` still scaffolds the compat `.codex-plugin/` layout [doc].
  - Bad manifest paths are silently ignored (a warning only) [src].
  - A root `plugin.json` without the Agent Plugins `$schema` is treated as "Unrelated", and Codex falls back to `.codex-plugin/`, `.claude-plugin/`, `.cursor-plugin/` [src].
  - A root `plugin.json` that is a symlink disables manifest detection [src].
  - Hook scripts must exist in the execution environment and be trusted before they run [doc].
