- `local.parity-membership` (4): true positive under R10; `claude-in-codex` and `codex-in-claude` look intentionally one-sided and `mcp-error-audit` and `voice-notify` may be, so each needs owner judgement between listing the plugin and recording a `membership` exception with its reason.
- `local.pin-missing` for `codex-in-claude`: true positive under R4; the `url` source has neither `sha` nor `ref`.
- `local.pin-missing` for `data-reasoning`: true positive under R4 as written; the `github` source deliberately tracks `ref: release`, which the owner can now declare as a channel in a `marketplace-policy.json`, turning the error into `local.pin-channel` (info).
- `policy.inferred` (both): true positive; neither repository has a policy file, and the message correctly names Copilot CLI as a tool that would also read the Claude catalog.
- `schema.claude-validate.unreachable` for `data-reasoning`: true positive; its root is both marketplace and plugin, so Claude Code's plugin-level validation cannot run there.
  After review of PR #1 the group reports `inconclusive` rather than `passed` in this case, because the plugin's own validation never ran (spec R12); the reports were regenerated at the same commits and only that status changed.
- No false positives were found.
