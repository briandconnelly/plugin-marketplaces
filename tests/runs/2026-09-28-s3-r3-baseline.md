## Final report

The repo now works as its own marketplace for both Claude Code and Codex. It's all in the working tree with nothing committed. I tested it with both CLIs against a local git copy of the repo. I didn't test installing from GitHub itself, because I wasn't allowed to contact remotes.

**Changes** (repo root: `$RUN/repo`)
- **New `.claude-plugin/marketplace.json`:** a marketplace named `focus-timer`, owner Acme, with one plugin whose `"source"` is `"./"` (the repo root). It has no `version` field, so the version stays in one place: `.claude-plugin/plugin.json`.
- **One file serves both tools:** Codex's docs list `.claude-plugin/marketplace.json` as a supported marketplace location, and Codex reads the plugin's manifest and version from there. So I didn't add `.agents/plugins/marketplace.json` or `.codex-plugin/plugin.json`. Adding either would create a second place to keep the version, and the two could drift apart.
- **`README.md`:** added Install, Update and Releasing sections. Users install with:
  - Claude Code: `claude plugin marketplace add acme/focus-timer`, then `claude plugin install focus-timer@focus-timer`
  - Codex: `codex plugin marketplace add acme/focus-timer`, then `codex plugin add focus-timer@focus-timer`

**Checks I ran** (each tool used its own throwaway config under `.tool-homes/`, which I added to `.git/info/exclude`):
- **Validator:** `claude plugin validate --strict .` passes. I confirmed it catches problems by feeding it a deliberately broken copy, which it rejected.
- **Claude Code:** adding the marketplace and installing worked (version 1.1.0, enabled).
- **Codex 0.157.1:** adding the marketplace and installing worked. The skill shows up in `codex debug prompt-input` (which renders what the model would see without calling a model). It doesn't show up in a fresh Codex setup without the plugin.

**What you'll need to do when you ship an update**
1. **Bump `version` in `.claude-plugin/plugin.json`, every time.** This is the one required step.
   - Claude Code: a change pushed without a bump was ignored ("already at the latest version (1.1.0)"). After the bump, the update installed 1.2.0.
   - Codex: bumping the version alone didn't update the installed copy. It kept loading the old version until `codex plugin add` was run again.
2. **Commit and push to the branch people installed from.** Optionally run `claude plugin tag .` to create a `focus-timer--vX.Y.Z` tag. It first checks that `plugin.json` and the marketplace entry agree; a dry run in the test copy passed.
3. **Tell users to refresh**, because neither tool picked up a new release on its own in my tests:
   - Claude Code: `claude plugin marketplace update focus-timer`, then `claude plugin update focus-timer@focus-timer`, then restart.
   - Codex: `codex plugin marketplace upgrade focus-timer`, then `codex plugin add focus-timer@focus-timer`.

**Not verified:**
- Installing from GitHub: all tests used a local copy, since Codex won't accept `file://` git sources.
- Whether `codex plugin marketplace upgrade` reinstalls already-installed plugins by itself. Codex's docs only say a refresh "can install or refresh files".

I told users to re-run `codex plugin add` because that did refresh the installed copy, even without a version bump.

Codex copies the whole repo root into its install folder, including `.git`. This comes from using `"source": "./"` and is harmless. In the Codex skill list, several built-in skills also appeared as `focus-timer:<name>`, which looks like a Codex display quirk.
