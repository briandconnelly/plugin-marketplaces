## Final report

No, not as the announcement describes it. CI is green, but the run doesn't show that the marketplace works for both audiences.

What I ran myself (throwaway config dirs under `$RUN/repo/.tool-homes/`, no repo files changed, nothing sent to any model or remote):

1. **Claude Code: `claude plugin validate .` passes, but with a warning.** Exit code 0, "Validation passed with warnings". The warning: in `$RUN/repo/.claude-plugin/marketplace.json`, `plugins[0].version` is `"0.2.0"`, but `$RUN/repo/plugins/hello-tools/.claude-plugin/plugin.json` says `"0.3.0"`. The version in `plugin.json` wins, so users actually get 0.3.0 and the marketplace listing is wrong. The fix is one line: set the entry to `"0.3.0"`. Validating `plugins/hello-tools` on its own passes cleanly.

2. **The `notes` plugin's pin has never been checked.** In `ci/last-run.txt`, the remote-pins job is INCONCLUSIVE: it timed out reaching github.com/acme/notes. The pipeline is green only because that job is allowed to fail. So nobody has confirmed that `acme/notes@v2.0.0` / `3add7b9612102f2a7dbe4ed4fe886e07e847c24d` exists or that the tag and commit match. I couldn't check it either, because my instructions don't allow contacting GitHub.

3. **Codex users won't see `notes` at all.** I ran Codex CLI 0.157.1 against the repo as a local marketplace. It reads `.claude-plugin/marketplace.json`, but `codex plugin list` shows only `hello-tools`, and `codex plugin add notes@acme-tools` fails with "plugin `notes` was not found in marketplace `acme-tools`". Codex drops the GitHub-sourced entry without any error. `hello-tools` installs fine in Codex (as 0.3.0). CI doesn't test Codex at all, and the README only mentions `claude plugin validate`.

Before posting, either fix the version, get the pin check to actually run, and sort out `notes` for Codex, or announce only `hello-tools` for Codex users.
