## Final report

The repository now works as its own marketplace for both Claude Code and Codex, through one new file: `.claude-plugin/marketplace.json`. I installed from it locally in both tools with throwaway config directories and both installs succeeded. Nothing was fetched from GitHub, so the `acme/focus-timer` shorthand itself is untested.

**What changed** (nothing is committed):
- **New `$RUN/s3/.claude-plugin/marketplace.json`**: a marketplace named `focus-timer` (owner Acme) with one plugin entry, `{"name": "focus-timer", "source": "./", "description": "Run focus sessions"}`. `"./"` points at the repo root, where the plugin already lives. The entry name matches the name in `plugin.json`.
- **`$RUN/s3/README.md`**: added install steps for each tool.
  - Claude Code: `claude plugin marketplace add acme/focus-timer`, then `claude plugin install focus-timer@focus-timer`.
  - Codex: `codex plugin marketplace add acme/focus-timer`, then `codex plugin add focus-timer@focus-timer`.
  - A short note says both tools read the version from `.claude-plugin/plugin.json`, so it needs a bump on every release.

**Checks I ran** (Claude Code 2.1.283, codex-cli 0.157.1, using a copy of the working tree without `.git`):
- **Claude Code:** `claude plugin validate` passed. Adding the marketplace and installing the plugin both succeeded. `claude plugin list` shows version 1.1.0, enabled, and `claude plugin details` lists the `focus-timer` skill.
- **Codex:** it found the marketplace through `.claude-plugin/marketplace.json`, which its docs describe as "legacy-compatible". Install succeeded, `codex plugin list` shows "installed, enabled 1.1.0", and the cached copy contains `skills/focus-timer/SKILL.md`.

**Limits of that testing:**
- I didn't start a Codex or Claude session, because that would contact the model providers. So I have not confirmed that the skill fires; I only confirmed install and that the files are in place.
- The first Codex install failed with "File name too long". That was caused by the test setup, not the repo: the Codex config directory sat inside the repo, and the `./` source copies the whole repo, so the copy kept nesting into itself. With the config directory outside the copied tree, the install worked. Real users won't hit this.

**Decision for you:** I did not add Codex's native `.agents/plugins/marketplace.json` or a Codex plugin manifest (`plugin.json` or `.codex-plugin/plugin.json`). Codex works today from the Claude file alone, and a second catalog would repeat the plugin list, which can drift out of sync. The catch is that Codex calls this path "legacy-compatible", so a future Codex release could drop it. If you'd rather not rely on that, the native file needs a plugin entry with `source: {source: "local", path: "./"}`, `policy.installation`, `policy.authentication` and `category`. I didn't test whether Codex prefers that file when both exist.

`.tool-homes/` holds the throwaway configs, the test copy and the test script (`t.sh`). I listed it only in `.git/info/exclude`, so it won't show in `git status` but isn't in `.gitignore`.
