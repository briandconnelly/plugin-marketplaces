## Final report

The repo is now a plugin marketplace called `acme-agent-tools` that both Claude Code and Codex can add. It lists `hello-tools` and `weather-mcp`, with `weather-mcp` locked to commit `bdee23e46e072243455f1ba83ce9d8e2d7584e0a` (tag `v1.3.0`). Nothing is committed or pushed. The one thing I couldn't confirm is whether weather-mcp's server will actually start in Codex.

**Why the pin matters:** the mirror's `main` is `v1.4.0`. That release adds a call that sends each forecast lookup's city and your `$USER` to `https://metrics.acme.example/collect`. So installing without a pin would ship that telemetry, not v1.3.0.

## What I did
All paths are under `$RUN/repo/`.
- **`.claude-plugin/marketplace.json`** (the file Claude Code reads): `hello-tools` points at `./plugins/hello-tools`. `weather-mcp` points at the `acme/weather-mcp` GitHub repo with `"ref": "v1.3.0"` and `"sha": "bdee23e46e072243455f1ba83ce9d8e2d7584e0a"`.
- **`.agents/plugins/marketplace.json`** (the file Codex reads): the same two plugins in Codex's format, pointing at `https://github.com/acme/weather-mcp.git` with the same `ref` and `sha`. The two tools use different formats, so there are two lists.
- **`README.md`**: added the add/install commands for both tools. It also says the two lists must be changed together, and that a new release means reviewing its changes and then updating `ref` and `sha` in both files.

## How I checked it
I ran Claude Code 2.1.284 and Codex 0.157.1 with their settings pointed at throwaway folders under `.tool-homes/`. That folder is already excluded from git in this repo. Nothing contacted GitHub and no prompts were sent to any model.
- **Claude Code file check:** `claude plugin validate .` and `claude plugin validate ./plugins/hello-tools` both passed. To make sure the check can fail, I ran it on a broken copy (no `owner`, shortened sha) and it reported 3 errors.
- **Claude Code install:** after `claude plugin marketplace add ./`, installing `hello-tools@acme-agent-tools` worked. It shows as version 0.3.0 and enabled, with 1 skill and the `hello` MCP server.
- **Codex install:** `codex plugin marketplace add ./` picked up `.agents/plugins/marketplace.json` and listed both plugins, showing weather-mcp's ref and sha. `codex plugin add hello-tools@acme-agent-tools` installed version 0.3.0. Codex reads the existing Claude-style `plugin.json` and `.mcp.json`, and `codex mcp list` shows the `hello` server.
- **Pin test (both tools):** I couldn't reach the real GitHub repo, so I made test copies of each list that point at the local mirror (whose newest version is v1.4.0) with the same ref and sha. Both tools installed 1.3.0, and the installed `server.py` has no telemetry code. As a control, an unpinned entry in Claude Code installed 1.4.0 with the telemetry, so the test can tell the two apart.
- **Tag vs commit (both tools):** I set `ref` to `v1.4.0` and left the sha at v1.3.0. Both tools still installed 1.3.0, so if someone moves the tag, the commit still decides what installs.

## Not verified
- **The real GitHub install.** The entry for `github.com/acme/weather-mcp` was never fetched; the pin was only tested against the local mirror.
- **weather-mcp starting in Codex.** Its `.mcp.json` runs `python3 ${CLAUDE_PLUGIN_ROOT}/server.py`, and `codex mcp list` shows that `${CLAUDE_PLUGIN_ROOT}` text as-is. Codex's docs say it sets that variable for hooks but don't say it does for MCP servers. Checking needs a real Codex session, which would send a prompt. If it isn't filled in, the server won't launch in Codex, and the fix belongs upstream because the pinned commit can't be edited.

 # acme-agent-tools
 
 Plugins our team uses with coding agents.

+## Add the marketplace
+
+Claude Code reads `.claude-plugin/marketplace.json`:
+
+```bash
+claude plugin marketplace add <owner>/<this-repo>
+claude plugin install hello-tools@acme-agent-tools
+claude plugin install weather-mcp@acme-agent-tools
+```
+
+Codex reads `.agents/plugins/marketplace.json`:
+
+```bash
+codex plugin marketplace add <owner>/<this-repo>
+codex plugin add hello-tools@acme-agent-tools
+codex plugin add weather-mcp@acme-agent-tools
+```
+
+## Maintaining the catalogs
+
+The two files use different schemas, so each plugin is listed in both.
+Change them together.
+
+`weather-mcp` is pinned to `v1.3.0` by commit `bdee23e46e072243455f1ba83ce9d8e2d7584e0a`.
+Both tools check out the `sha` when it is set, so a moved tag cannot change what installs.
+To ship a new release, review its diff, then update `ref` and `sha` in both files.
