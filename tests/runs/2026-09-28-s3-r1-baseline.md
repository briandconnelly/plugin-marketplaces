## Final report

The repository now works as its own marketplace in both Claude Code and Codex. I tested install and update in both tools against a local git copy of the repo, but not against the real `acme/focus-timer` on GitHub. None of this is committed, so the three changes below are in the working tree for you to review.

## What changed
All paths are under `$RUN/repo/`.
- **`.claude-plugin/marketplace.json`** (new, for Claude Code): marketplace `focus-timer`, owner Acme, one plugin entry whose source is `"./"`, meaning the repo root.
- **`.agents/plugins/marketplace.json`** (new, for Codex): the same marketplace name, a plugin source with path `"./"`, the policy set to available to install, and category `Productivity`.
- **`README.md`**: now has install, update and release instructions.

Users install with:
- **Claude Code:** `claude plugin marketplace add acme/focus-timer`, then `claude plugin install focus-timer@focus-timer`
- **Codex:** `codex plugin marketplace add acme/focus-timer`, then `codex plugin add focus-timer@focus-timer`

There is no separate Codex manifest. Codex read the plugin's name and version from the existing `.claude-plugin/plugin.json` and installed it as 1.1.0.

## How I checked it
- `claude plugin validate .` passes with no warnings. It warned about a missing marketplace description, so I added one.
- Neither tool accepts a `file://` source, so I served a copy of the repo over git HTTP on `127.0.0.1`. From there both tools added the marketplace, installed 1.1.0, and then updated.
- All tool config went into throwaway directories under `.tool-homes/`. That folder doesn't show up in `git status`, so you can delete it or leave it.

## What to do when you ship an update
1. **Bump `version` in `.claude-plugin/plugin.json`** and push. This one field sets the version for both tools, so don't put a `version` in either marketplace file.
   - When I pushed a change without a bump, Claude Code reported "already at the latest version (1.1.0)" and users kept the old files.
   - Codex behaved differently: it quietly replaced the files in the existing 1.1.0 install with the new content. Forgetting the bump therefore leaves the two tools' users running different code under the same version number.
2. **Tell users how to update:**
   - **Claude Code:** `claude plugin marketplace update focus-timer`, then `claude plugin update focus-timer@focus-timer`. Running `claude plugin update` alone did not see 1.2.0 until the marketplace was refreshed first. After updating, Claude Code asks for a restart. Automatic updates are off by default; each user can turn them on in `/plugin` → Marketplaces (according to the docs; I didn't test that).
   - **Codex:** `codex plugin marketplace upgrade focus-timer`. That one command refreshed the marketplace and moved the install to 1.2.0.
3. **Keep the names identical.** The marketplace name and plugin name must stay `focus-timer` in both marketplace files, because users type `focus-timer@focus-timer`. Renaming either one breaks existing installs.

Once this is pushed, a quick check from the real GitHub repo in each tool would confirm it; I couldn't run that here.
