## Final report

review-kit now works in Codex and GitHub Copilot CLI, and Claude Code still loads everything it did before. I checked all three tools (claude 2.1.284, codex-cli 0.157.1, copilot 1.0.89) in throwaway config with outbound network blocked. No model sessions were opened and no plugin code was run. The changes are staged in `$RUN/repo` but not committed.

**What works where**

| Component | Claude Code | Codex | Copilot CLI |
| --- | --- | --- | --- |
| `/review` | yes | yes (listed as `review-kit:review`) | yes |
| `reviewer` agent | yes | no, Codex doesn't load agents | unknown: no command shows agents |
| `SessionStart` hook | yes | should run once the user trusts it, but I couldn't confirm it | unknown: no command shows hooks |
| `review` MCP server | yes, with the API key | yes, but without the API key | yes, but without the API key |
| API key setting (`api_key`) | yes | no | no |

- **Claude Code:** it lists the same things as the original plugin: 1 skill, 1 agent, 1 hook, 1 MCP server, version 2.0.0. The MCP server setup is unchanged.
- **Codex:** it lists and installs 2.0.0 and sets up the server with the real install path. To see the skill I used a stand-in copy with only the manifest and skill, because the command that shows it also starts the plugin's MCP server.
- **Copilot CLI:** it installs 2.0.0 and reports "Installed 1 skill". `copilot skill list` shows `review`, and `copilot mcp get review` shows the server.
- **MCP server startup:** Copilot shows `${PLUGIN_ROOT}` unexpanded in the command, but it also puts `PLUGIN_ROOT` in the server's environment. I wrote the command so the shell fills in the path either way, which should cover this. I didn't see it actually start in either tool, because starting it runs plugin code. Copilot has no command that starts servers without a session.
- **API key:** in Codex and Copilot the server never gets `REVIEW_API_KEY`. The new portable format has no per-user settings and says not to put secrets in the config, so anything that needs the key won't work in those tools.
- **Already broken, not fixed by me:** `server/run.sh` runs `python3 -m review_server`, and that module isn't in the repo. The server can't start in any tool unless users install it separately, and the README now says so.

**What I changed**
- **New Codex/Copilot manifest:** `plugin.json` at the root, name `review-kit`, version 2.0.0. It matches `.claude-plugin/plugin.json`, which is unchanged.
- **New `mcp.json`:** the `review` server in the portable format. `.mcp.json` is unchanged for Claude Code.
- **Command moved to a skill:** `commands/review.md` is now `skills/review/SKILL.md`. With the new root manifest, Codex and Copilot stop reading `commands/`, and a skill is the only way to keep `/review` there. Claude Code shows it the same way as before.
- **New Codex catalog:** `.agents/plugins/marketplace.json`.
- **`.claude-plugin/marketplace.json`:** the entry now has a description that mentions the hook, the MCP server and the external service with your API key. It is still what Claude Code and Copilot read.
- **New `marketplace-policy.json`:** says the targets are Claude Code, Codex and Copilot CLI.
- **`README.md`:** install steps for each tool, the same what-works-where table, and a note to keep the two versions and the two MCP files matching.
