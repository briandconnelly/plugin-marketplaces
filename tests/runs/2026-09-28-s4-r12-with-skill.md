## Final report

review-kit now installs from the same repo in Claude Code, Codex and Copilot CLI. Claude Code gets exactly the same plugin as before. The review skill and the MCP server's settings load in all three tools. The reviewer agent and the API key setting only work in Claude Code. Nothing is committed; all changes are staged in `$RUN/repo`.

**Changes** (I added new files and removed nothing except the old command file, which became a skill):
- **`plugin.json` and `mcp.json`** (new, at the repo root): the shared plugin format that Codex and Copilot CLI read. Once these exist, both tools read only these two files. The MCP server is `./server/run.sh` with no environment variables.
- **`skills/review/SKILL.md`**: this replaces `commands/review.md`. With the shared manifest in place, Codex and Copilot CLI stop reading `commands/`, so only a skill still reaches their users. Claude Code treats a command and a skill the same way, and its component list is identical before and after.
- **`.agents/plugins/marketplace.json`** (new): the catalog Codex reads.
- **`.claude-plugin/marketplace.json`**: now used by Claude Code and Copilot CLI. I added an entry description that says the plugin runs a SessionStart hook and a local MCP server that uses an external service with your API key. The Codex catalog has the same description.
- **`marketplace-policy.json`** (new): declares the three target tools.
- **`README.md`**: install commands for each tool and a table of what works where.
- **Not changed:** `.claude-plugin/plugin.json`, `.mcp.json`, `agents/`, `hooks/`, `scripts/`, `server/`. The version is 2.0.0 in both manifests; a release has to change both.

**What works in each tool**

| | Claude Code | Codex | Copilot CLI |
|---|---|---|---|
| `review` skill | yes, same as before | yes, listed as `review-kit:review` | yes |
| `reviewer` agent | yes | no (not in the list of skills and agents Codex presents) | unknown: no command shows it |
| SessionStart hook | yes | runs only after the user trusts the plugin's hooks (from the reference, not tested) | unknown: no command shows it |
| `review` MCP server | yes | set up with the correct absolute path | set up with the correct absolute path |
| API key setting (`${user_config.api_key}`) | yes | no | no |

- **MCP server:** before this change, Codex and Copilot CLI were given the text `${CLAUDE_PLUGIN_ROOT}/server/run.sh` literally, so the server could not start. Both now resolve it to the installed `server/run.sh`. I did not start the real server in any tool, so it is unconfirmed that it actually runs.
- **API key:** in Codex and Copilot CLI the server no longer gets `REVIEW_API_KEY` at all. Before, it got the literal placeholder text instead of a key. The shared format has no settings feature and says secrets should not go in its config files. Users of those tools would have to supply the key some other way, and none has been tested.
- **Skill name in Codex:** Codex used to convert the command into a skill called `source-command-review`; it is now `review-kit:review`.
- **Existing problem you should know about:** `server/run.sh` runs `python3 -m review_server`, but no `review_server` module is in this repo. Unless it is installed separately, the MCP server won't start in any tool, Claude Code included.

**Checks run** (every tool ran with throwaway settings under `.tool-homes/`, outbound network blocked, on a clean export of the staged files; on claude 2.1.284, codex-cli 0.157.1 and copilot 1.0.89, the same versions the skill's references were checked against):
- **Validator:** file format, policy, shared-format and local checks all passed. I confirmed it catches problems by setting a different version in one manifest on a scratch copy; it reported the mismatch as an error. Claude's own validation of the plugin couldn't run from the validator here because the repo root is both marketplace and plugin.
- **`claude plugin validate --strict`:** 0 errors and 0 warnings, both on the catalog and on a copy with the catalog file removed.
- **Discovery:** each tool added the marketplace and listed review-kit (Codex `plugin list --available`, Copilot `marketplace browse`).
- **Load, Claude Code:** `claude --plugin-dir … plugin details` shows the same skill, agent, hook and MCP server before and after.
- **Load, Codex:** `plugin add` installed version 2.0.0, and `mcp list` shows the resolved server path. `debug prompt-input` lists `review-kit:review` and no `reviewer`. I ran that on a stand-in copy whose `run.sh` and `start.sh` were replaced with scripts that do nothing, because it starts plugin servers.
- **Load, Copilot CLI:** `plugin install` reported "Installed 1 skill", `skill list` shows `review`, and `mcp get review` shows the resolved path.
- **Remote:** not run; the only source is a local path, so there is nothing pinned to check.
