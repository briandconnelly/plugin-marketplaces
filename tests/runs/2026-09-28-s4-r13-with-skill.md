## Final report

I've made review-kit installable in Codex and GitHub Copilot CLI from the same repo, and it still loads the same way in Claude Code. All three tools installed it in throwaway configuration with outbound network blocked. The changes are staged but not committed.

**What I changed** (all under `$RUN/repo/`). Nothing Claude Code reads was deleted except `commands/review.md`, which became a skill.
- **Command converted to a skill:** I moved `commands/review.md` to `skills/review/SKILL.md` and added `name: review` to its frontmatter. The body is unchanged. Once a plugin has the new root `plugin.json`, Codex and Copilot CLI stop reading `commands/`, so a skill is the only way `/review` reaches their users. Claude Code treats both as the same `/review`.
- **New root `plugin.json`:** the portable (Agent Plugins 1.0) manifest, with name `review-kit` and version `2.0.0`, matching `.claude-plugin/plugin.json`.
- **New `mcp.json`:** declares the `review` server as `"type": "stdio"` with `"command": "./server/run.sh"` and `"cwd": "${PLUGIN_ROOT}"`. It passes no API key, because that key comes from a Claude-only setting (`userConfig`) and the portable format has no equivalent.
- **New `marketplace-policy.json`:** declares all three tools as readers. I kept the single `.claude-plugin/marketplace.json` instead of adding a second catalog, because its one entry is a relative path (`./`) and all three tools accept that.
- **`.claude-plugin/marketplace.json`:** the entry description now says the plugin runs a SessionStart hook and a local Python MCP server that uses a review-service API key.
- **`README.md`:** now has install commands and a what-works-where table for all three tools.

**What works in each tool** (from the install and listing commands below, except where marked):

| Component | Claude Code | Codex | Copilot CLI |
| --- | --- | --- | --- |
| `/review` skill | yes (listed) | not confirmed by a command; the files are in the install and Codex is documented to load `skills/` | yes (`copilot skill list` shows it) |
| `reviewer` agent | yes (listed) | no, Codex does not load plugin agents (documented) | unknown: no command shows agents |
| SessionStart hook | yes (listed) | should run once the user trusts it (documented); I did not see it run | unknown: no command shows hooks |
| `review` MCP server | yes, with the API key | configured, with a real path to `run.sh` | configured, with a real path to `run.sh` |
| API key prompt | yes | no | no |

- **The API key does not reach the server in Codex or Copilot CLI.** In Codex the server's allowed environment variables are empty, and in Copilot CLI only the plugin-path variables are passed. The server would need to get `REVIEW_API_KEY` another way there, and I did not observe whether it does.
- **The server needs Python code this repo doesn't contain.** `server/run.sh` runs `python3 -m review_server`, which isn't in the repo, so the server works in any tool only if `review_server` is already installed on the machine. This was true before the change too.
- **No change for Claude Code users.** `claude plugin details` shows exactly the same list (1 skill, 1 agent, 1 hook, 1 MCP server, version 2.0.0) for the original layout and the new one.

**Checks run:**
- **Schema and local checks:** the validator passed with exit 0. To confirm it can fail, I raised the version in a copy's `plugin.json` and it reported a version mismatch. Claude Code's own validator (`claude plugin validate --strict`) passed on the catalog and, from a separate copy, on the plugin itself.
- **Catalog discovery:** each tool added the marketplace and listed `review-kit` at version 2.0.0.
- **Package load:** all three installed it. Codex and Copilot CLI read the new `mcp.json`, not the Claude-only `.mcp.json`.
- **Remote:** not applicable, since there is no remote source.
- **Not run:**
  - I didn't start the MCP server or run the hook in any tool, since that would execute the plugin's code.
  - I didn't open a model session in any tool.
  - I didn't use Codex's command that lists the skills it would present (`codex debug prompt-input`), because it starts plugin MCP servers.

The installed tool versions (claude 2.1.284, codex-cli 0.157.1, copilot 1.0.89) match what the skill's references were checked against, so no facts needed re-checking. One zsh quoting mistake made my first round of Copilot commands fail; they all succeeded when re-run.

**Things to know before releasing:**
- The two manifests must keep the same name and version. Bump the version on every release, because Claude Code users don't receive a pushed change without a bump.
- Because the plugin root is the repo root, `README.md` and `marketplace-policy.json` get copied into installs. That does no harm.
