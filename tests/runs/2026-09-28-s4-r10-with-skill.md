## What I did
review-kit now installs in Codex and GitHub Copilot CLI, and Claude Code still loads exactly the same components as before.
I followed the plugin-marketplaces skill's "Port a plugin" and "Create a marketplace" steps.
The changes are staged in `$RUN/repo` but not committed.

- **Added** `$RUN/repo/plugin.json`: the portable manifest, which Codex and Copilot CLI read. It uses the Agent Plugins 1.0 format (`$schema`, name `review-kit`, version `2.0.0`, description, author), and its name and version match `.claude-plugin/plugin.json`.
- **Added** `$RUN/repo/mcp.json`: the same `review` server as a portable stdio entry, `command: "sh"`, `args: ["${PLUGIN_ROOT}/server/run.sh"]`.
  - It has no `env` block, because the portable format has no user settings and says secrets must not go in `env`.
- **Moved** `commands/review.md` to `$RUN/repo/skills/review/SKILL.md` and added `name: review`.
  - This was needed because, once `plugin.json` exists, Codex and Copilot CLI stop reading `commands/`, so they would lose the command.
  - The body did not change.
- **Updated** `$RUN/repo/.claude-plugin/marketplace.json`: the entry now has a description saying the plugin runs a local MCP server that uses an API key for the review service, and a SessionStart hook in Claude Code.
- **Added** `$RUN/repo/marketplace-policy.json`: it declares all three tools as readers.
  - It also records why one shared catalog is enough: the only entry uses the `./` source, which all three tools accept, so there is no `.agents/` or `.github/` catalog.
- **Updated** `$RUN/repo/README.md` with install commands and a table of what works in each tool.

Claude Code still reads only `.claude-plugin/plugin.json`, `.mcp.json`, `hooks/`, and `agents/`, and none of those changed.
