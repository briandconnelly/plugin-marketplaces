## Final report

## Audit of the acme-tools marketplace

The marketplace isn't ready to announce. Of the 7 entries, 3 can't be installed in Claude Code or Codex, or are broken once installed. Several more fail silently, especially in Codex.

I read every file under `$RUN/s6`: `README.md`, `.claude-plugin/marketplace.json`, and each `plugins/*/.claude-plugin/plugin.json` and `SKILL.md`. There was no `s6-upstream` directory. I then tested the marketplace in both tools, using throwaway config directories under `.tool-homes/`:
- **Claude Code 2.1.283:** ran `claude plugin validate`, then `claude plugin marketplace add` and `claude plugin install` for each local plugin.
- **Codex CLI 0.157.1:** ran `codex plugin marketplace add`, `codex plugin add` and `codex plugin list`.

I didn't install the two remote plugins (`notes`, `remote-x`), because that would have contacted GitHub. Afterwards I deleted `.tool-homes/`, and `git status` is clean. No repo files were changed.

### Blockers

1. **`fmt` can't be installed in either tool** (`marketplace.json`, the `fmt` entry has `"source": "plugins/fmt"`, with no leading `./`).
   - Claude: `claude plugin validate .` fails with `plugins.2.source: Invalid input`, and `claude plugin install fmt@acme-tools` fails with "marketplace entry is invalid: source: Invalid input". The other entries still install.
   - Codex: the entry is silently dropped. It doesn't appear in `codex plugin list`, and `codex plugin add fmt@acme-tools` says "plugin `fmt` was not found". There's no warning, even with `RUST_LOG=warn`.
   - Fix: change the source to `"./plugins/fmt"`. With only that change, a copy of the marketplace validates in Claude with just the version warning (item 5).

2. **`guard` installs but doesn't load in Claude** (`marketplace.json`, the `guard` entry has `"hooks": "./hooks/hooks.json"`).
   - `claude plugin list` shows `✘ failed to load`: "Hook load failed: hooks: the file-path and array forms are not yet supported in a marketplace entry. Define hooks in the plugin's own hooks/hooks.json (or its plugin.json), or inline them here as an object…"
   - The file it points to doesn't exist either: `plugins/guard/` contains only `.claude-plugin/` and `skills/`.
   - `claude plugin validate` doesn't catch this. It passes.
   - Codex installs `guard` with no hooks, so its "guard" does nothing there.

3. **`lint` can't be installed in Codex, and has two different names in Claude.** The marketplace entry is named `lint`, but `plugins/lint/.claude-plugin/plugin.json` says `"name": "linter"`, and so does the skill.
   - Codex: `codex plugin add lint@acme-tools` fails with "plugin.json name `linter` does not match marketplace plugin name `lint`".
   - Claude: the install succeeds silently as `lint@acme-tools`, while `linter@acme-tools` is "not found". The validator doesn't flag the mismatch.

4. **`notes` is invisible to Codex users.** Codex 0.157.1 silently skips entries with `"source": "github"`. I tested the variants in isolated copies:
   - `github` with ref and sha, ref only, sha only, or neither: all give "No plugins found".
   - The same repo as `"source": "url"` (or `git-subdir`) is listed.
   - Claude's validator accepts the `github` form.
   - I couldn't check offline that the sha `3add7b9…` is really the commit tagged `v2.0.0`. Confirm that before announcing.

### Should fix

5. **The `deploy` versions disagree.** The marketplace says `2.0.0` and `plugin.json` says `1.9.0`. Claude's validator warns that plugin.json wins and the entry's version is silently ignored. Both tools installed 1.9.0. Anyone told about "deploy 2.0.0" will get 1.9.0.

6. **`remote-x` points at a branch and isn't pinned** (`"source": "url"`, `"ref": "main"`, no `sha`). Every install or update pulls whatever `main` is at that moment. That's a supply-chain and reproducibility risk, and it's inconsistent with `notes`, which is pinned. Add a `sha`, or point at a tag plus a sha.

7. **None of the validators catch the most serious problems.** `claude plugin validate` passes the `guard` hooks problem (item 2) and the `lint` name mismatch (item 3). Codex drops invalid entries without saying so (items 1 and 4). A green validator run isn't a sufficient pre-announcement check: add a real install smoke test in both tools.

### Quality and discoverability

8. **Descriptions won't help anyone find or trigger these plugins.**
   - The marketplace entries say just "ok", "notes", "fmt", and so on.
   - The `plugin.json` descriptions say "Use deploy" and the like.
   - Every SKILL.md description has the form "Use when you want to use X", and the bodies are one line ("Use deploy.").
   - Agents won't know when to invoke these skills, and users can't tell what they do. For `deploy` in particular, users and agents can't tell what it acts on or whether it's safe to run.

9. **The README gives no install instructions for either client.** It's 3 lines. It should give the Claude `/plugin marketplace add …` and Codex `codex plugin marketplace add …` commands and list the plugins and what each does.

10. **Minor metadata gaps:** `owner` has no email or URL, and there's no marketplace-level version, homepage or repository.

### What works

- `ok-tools` and `deploy` install and are enabled in both tools.
- Codex reads `.claude-plugin/marketplace.json` and `.claude-plugin/plugin.json` directly, so no separate Codex manifest is needed for those plugins to install.
