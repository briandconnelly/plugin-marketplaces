## Final report

The repository at $RUN/repo now works as its own marketplace for both Claude Code and Codex. Nothing is committed or pushed yet.

**Files I added or changed**
- `$RUN/repo/.claude-plugin/marketplace.json` is the Claude Code marketplace. It's named `focus-timer`, and its single entry has `"source": "./"` because the plugin is the repo root.
- `$RUN/repo/.agents/plugins/marketplace.json` is the Codex marketplace. It has the same name and uses source `{"source":"local","path":"./"}`, plus the `policy` and `category` fields that Codex requires.
- `$RUN/repo/README.md` now has install, update and release steps for both tools.
- `.claude-plugin/plugin.json` is unchanged. It stays the only place the version (1.1.0) is set, because Codex reads it too. Neither marketplace entry sets a version, so there's nothing to fall out of sync.

**How users install it**
- Claude Code: `claude plugin marketplace add acme/focus-timer`, then `claude plugin install focus-timer@focus-timer`.
- Codex: `codex plugin marketplace add acme/focus-timer`, then `codex plugin add focus-timer@focus-timer`.

**What you'll need to do when you ship an update**
1. **Bump `version` in `.claude-plugin/plugin.json` every release.** This is the step that matters. If you push without a bump, Claude Code users stay on their old copy even after running `claude plugin update`, which reports "already at the latest version". Codex is more forgiving and picked up an unbumped change, but Claude Code needs the bump.
2. **Don't add `version` to either marketplace file.** If it's also in the Claude marketplace entry and doesn't match, Claude Code quietly uses the `plugin.json` value. Plain `claude plugin validate` only warns about this and still exits 0.
3. **Run `claude plugin validate --strict .` before pushing.** `--strict` makes that mismatch warning fail the check.
4. **Commit and push to the default branch.** Optionally tag the release with `claude plugin tag --push`, which creates a `focus-timer--v<version>` tag after checking that the versions agree.
5. **Users pull updates themselves.**
   - Claude Code: `claude plugin marketplace update focus-timer` then `claude plugin update focus-timer@focus-timer`, followed by a restart. They can also turn on auto-update in `/plugin`, which is off by default.
   - Codex: `codex plugin marketplace upgrade focus-timer`.

**How I checked it**
Everything ran with isolated `HOME`, `XDG_CONFIG_HOME`, `CODEX_HOME` and `CLAUDE_CONFIG_DIR` under `.tool-homes/`, which is git-excluded. No model was prompted and no remote was contacted.
- `claude plugin validate --strict .` passes. I confirmed it can fail: it flags a version mismatch in a copy where I set one on purpose.
- I pointed an unresolvable address (`https://git.invalid/...`) at a local bare copy of the repo with a git `insteadOf` rule. That let me test the git-clone path for real in Claude Code 2.1.284 and Codex 0.157.1.
  - Both tools added the marketplace and installed the plugin.
  - Codex read `.agents/plugins/marketplace.json` and took version 1.1.0 from `.claude-plugin/plugin.json`.
- Pushing a change without a version bump: Claude Code didn't deliver it, while Codex's `marketplace upgrade` updated its cached copy in place.
- Pushing a bump to 1.2.0: both tools updated.

**Not checked**
- The real `acme/focus-timer` repo on GitHub. Claude Code's shorthand install first tries SSH, and users without a GitHub SSH key may need `CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1`.
- Whether Codex refreshes marketplaces in the background.
- The ChatGPT desktop app.
- Codex's docs prefer a portable root `plugin.json`, but I deliberately didn't add one, because it would mean keeping the version in two places.
