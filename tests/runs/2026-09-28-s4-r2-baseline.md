## Final report

review-kit now installs in Codex CLI (0.157.1) and GitHub Copilot CLI (1.0.86), and Claude Code still loads the same components as before. I left the Claude files untouched. The changes are uncommitted.

I tested each tool by installing the plugin from a local folder, with throwaway config directories and network access blocked. I used a stand-in for the review server, because the repo doesn't contain the `review_server` Python module that `server/run.sh` starts. No prompts were sent to any model.

**What I changed** (all in `$RUN/repo/`)
- **`.codex-plugin/plugin.json`** (new): a Codex-only manifest. It exists to point Codex at `.codex-mcp.json`, because Codex doesn't fill in `${CLAUDE_PLUGIN_ROOT}` in the server's `command`, so the server failed to start. Its name, version and description repeat `.claude-plugin/plugin.json`, so the two must be updated together.
- **`.codex-mcp.json`** (new): starts the server as `sh server/run.sh` from the plugin folder, and passes `REVIEW_KIT_API_KEY` from the user's environment. This was the only one of four variants I tried that started in Codex.
- **`server/run.sh`**: Copilot was handing the server the literal text `${user_config.api_key}` as its API key, and Codex passed no key. The script now uses `REVIEW_KIT_API_KEY` whenever `REVIEW_API_KEY` is empty or still that placeholder. A real key from Claude Code is kept. I checked all five combinations.
- **`README.md`**: install commands for each tool, how to supply the API key, and the table below.

**What works where**

| Component | Claude Code | Codex | Copilot CLI |
|---|---|---|---|
| Marketplace (`.claude-plugin/marketplace.json`) | yes | yes, read as-is | yes, but only with an absolute path (`./x` is read as a GitHub repo) |
| `commands/review.md` | `/review-kit:review` | Codex converts it on install into a skill called `review-kit:source-command-review`; there's no slash command | `/review-kit:review` (plain `/review` is Copilot's built-in reviewer) |
| `agents/reviewer.md` | yes | **no**: Codex plugins can't include agents | yes, as `review-kit:reviewer` |
| `review` MCP server | yes | yes, confirmed to start and list tools | yes, confirmed to start |
| API key prompt (`userConfig`) | yes | **no**: user must export `REVIEW_KIT_API_KEY` | **no**: user must export `REVIEW_KIT_API_KEY` |
| SessionStart hook | yes | registered, but Codex marks it untrusted and skips it until the user approves it in its hook review | **not confirmed** (see below) |

**Not verified**
- **Copilot hook:** its docs say the Claude hook format is supported, but I couldn't see it run. A test hook of my own didn't fire in my setup either, so this proves nothing either way.
- **Codex hook:** I didn't see it run after approval.
- **Claude Code key prompt:** I didn't test it end to end, because saving the key needs the real keychain. Claude Code's manifest check passes and it still sees the same command, agent, hook and MCP server. Its server also started with the new `run.sh`.
- **Installing from GitHub:** I didn't try `OWNER/REPO` installs; everything was tested from a local folder.

**Also worth knowing**
- Copilot always uses the root `.mcp.json`, even if a manifest names a different MCP config. That's why the key problem had to be fixed in `run.sh`, not with a Copilot-only config file.
- This was already true before my changes: opening the review-kit repo itself in Claude Code (and likely Copilot) also picks up its root `.mcp.json` as that project's own MCP settings, which fails there because `CLAUDE_PLUGIN_ROOT` isn't set outside a plugin.
- The MCP server won't work in any of the three tools until `review_server` is installed or added to the repo.

I deleted the throwaway `.tool-homes/` directory when I finished.

+Claude Code collects the key as `userConfig.api_key` (`/plugin configure review-kit@review-kit`) and keeps it in secure storage.
+Codex and Copilot CLI have no equivalent prompt.
+For them, export the key before starting the tool:
+
+```sh
+export REVIEW_KIT_API_KEY=...
+```
+
+`server/run.sh` passes it to the server as `REVIEW_API_KEY` whenever the host did not supply a real value.
+
+## What works where
+
+| Component | Claude Code | Codex CLI | Copilot CLI |
+| --- | --- | --- | --- |
+| Review command (`commands/review.md`) | `/review-kit:review` | Converted on install to the skill `review-kit:source-command-review`; ask for it or mention it by name | `/review-kit:review` (plain `/review` is Copilot's built-in reviewer) |
+| `reviewer` agent (`agents/reviewer.md`) | Yes | No: Codex plugins cannot ship agents | Yes, as `review-kit:reviewer` |
+| `review` MCP server | Yes (`.mcp.json`) | Yes (`.codex-mcp.json`, via `.codex-plugin/plugin.json`) | Yes (`.mcp.json`) |
+| SessionStart hook | Yes | Loaded, but skipped until you trust it in Codex's hook review | Declared in the supported Claude format; not observed running |
+| API key prompt | Yes | No: use `REVIEW_KIT_API_KEY` | No: use `REVIEW_KIT_API_KEY` |
+
+## Layout
+
+- `.claude-plugin/` holds the Claude Code manifest and the marketplace that all three tools read.
+- `.codex-plugin/plugin.json` exists only to point Codex at `.codex-mcp.json`, because Codex does not expand `${CLAUDE_PLUGIN_ROOT}` in an MCP `command`.
+  Keep its `name`, `version`, and `description` in step with `.claude-plugin/plugin.json`.
+- Do not edit `.mcp.json` for Copilot's sake: Copilot always prefers a root `.mcp.json` over any manifest `mcpServers` entry.
