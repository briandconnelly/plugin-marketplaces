## Final report

The one real gap: in Codex and Copilot CLI the MCP server gets no API key, so anything it does with the review service will probably fail there. Nothing is committed; the changes are in the working tree of `$RUN/repo`.

**What changed** (the existing Claude Code files are untouched):
- **`plugin.json` and `mcp.json` (new, at the repo root):** the portable format that Codex and Copilot CLI read. Name and version (2.0.0) match `.claude-plugin/plugin.json`. The MCP server is set to `./server/run.sh`, with no key setting.
- **`commands/review.md` became `skills/review/SKILL.md`:** once a root `plugin.json` exists, Codex and Copilot CLI stop reading `commands/`, so converting the command to a skill is the only way to keep `/review` in all three tools. I moved it with `git mv` and added `name: review`; the body is unchanged.
- **`.claude-plugin/marketplace.json`:** the entry description now says the plugin runs a local MCP server that talks to an external review service using your API key, and a SessionStart hook. The "external service" part comes from the `userConfig` wording "Key for the review service".

 # review-kit
 
-Code review helpers for Claude Code.
+Code review helpers for Claude Code, Codex, and GitHub Copilot CLI.
+
+review-kit runs code on your machine: a local MCP server (`server/run.sh`, which starts `python3 -m review_server`) that talks to an external review service, and, in Claude Code, a `SessionStart` hook (`scripts/start.sh`).
+
+## Install
+
+| Tool | Commands |
+| --- | --- |
+| Claude Code | `claude plugin marketplace add <repo>`, then `claude plugin install review-kit@review-kit` |
+| Codex | `codex plugin marketplace add <repo>`, then `codex plugin add review-kit@review-kit` |
+| Copilot CLI | `copilot plugin marketplace add <repo>`, then `copilot plugin install review-kit@review-kit` |
+
+## What works where
+
+| Component | Claude Code | Codex | Copilot CLI |
+| --- | --- | --- | --- |
+| `review` skill (formerly the `/review` command) | yes | yes | yes |
+| `review` MCP server | yes | configured, without the API key | configured, without the API key |
+| Review API key prompt (`userConfig`) | yes | no | no |
+| `reviewer` agent | yes | no | not verified |
+| `SessionStart` hook | yes | expected after you trust the plugin's hooks; not verified | not verified |
+
+In Codex and Copilot CLI the MCP server does not receive `REVIEW_API_KEY`, because neither tool supports Claude Code's `userConfig`.
+
+## Layout
+
+- `.claude-plugin/plugin.json` and `.mcp.json`: the Claude Code manifest and MCP configuration.
+- `plugin.json` and `mcp.json`: the portable [Agent Plugins](https://agent-plugins.org/) manifest and MCP configuration, read by Codex and Copilot CLI.
+- `.claude-plugin/marketplace.json`: the one catalog all three tools read.
+- `marketplace-policy.json`: the tools this marketplace targets.
+
+Keep `version` equal in `.claude-plugin/plugin.json` and `plugin.json`, and bump it on every release: Claude Code users do not receive a change whose version did not change.
