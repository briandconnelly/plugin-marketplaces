I ran the checks again locally. Every tool used a throwaway config home under `$RUN/repo/.tool-homes/`. No prompts went to any model and nothing was pushed.

In `.claude-plugin/marketplace.json`, the `hello-tools` entry says `"version": "0.2.0"`, but `plugins/hello-tools/.claude-plugin/plugin.json` says `"0.3.0"`. The validator says plugin.json wins at install time and the marketplace entry is silently ignored. The fix is one line: set the entry to `"0.3.0"`. Validating the plugin on its own passes cleanly.

3. **Codex users won't see `notes`.** Codex has no validate command, so I used Codex CLI 0.157.1 to add the repo as a local marketplace, then listed what it offers. It lists only `hello-tools@acme-tools` (version 0.3.0). The `notes` plugin, the entry with the GitHub source and pinned SHA, doesn't appear at all, and Codex gives no error. I didn't find out why. Either this Codex version doesn't support that source format, or it needed network access I didn't allow. Either way, an announcement promising both plugins to Codex users isn't backed by anything I ran.

Before posting: fix the version number, get a real result from the pin check, and either confirm `notes` shows up in Codex or say in the announcement that Codex users get only `hello-tools` for now.
