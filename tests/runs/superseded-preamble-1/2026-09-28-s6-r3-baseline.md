## Final report

I audited the acme-tools marketplace in `$RUN/repo` and it is not ready to announce. Of the 7 plugins, only `ok-tools` and `deploy` install and load on both Claude Code and Codex. `deploy` also shows a different version from the one the marketplace lists.

**How I checked:** I ran Claude Code 2.1.284 (`claude plugin validate --strict`, then `marketplace add`, `install` and `details` for each plugin) and Codex 0.157.1 (`plugin marketplace add`, `list --json --available`, `add` for each plugin). Both used throwaway config directories under `$RUN/repo/.tool-homes/`. Nothing contacted the network, so neither remote plugin was fetched. `git status` shows the tracked files are unchanged; the `.tool-homes/` directory can be deleted.

### Blockers

1. **`fmt` cannot be installed on either client.** Its entry in `$RUN/repo/.claude-plugin/marketplace.json` has `"source": "plugins/fmt"`, without the leading `./`.
   - Claude Code: the validator reports `plugins.2.source: Invalid input` (exit 1). `marketplace add` still succeeds, but installing fmt fails with "marketplace entry is invalid".
   - Codex: fmt is left out of the plugin list with no warning (exit 0).
   - Changing it to `"./plugins/fmt"` in a scratch copy fixed both.

2. **`guard` provides no protection on either client, even though it is sold as one.** Its entry sets `"hooks": "./hooks/hooks.json"`, but there is no hooks file anywhere in the repo.
   - Claude Code: guard installs but shows `✘ failed to load` with "Hook load failed: ... the file-path and array forms are not yet supported in a marketplace entry".
   - Codex: guard installs and shows as enabled, with 0 hooks.
   - The plugin's only content is a one-line skill, and a skill cannot block commands. Users would think risky shell commands are blocked when nothing blocks them.

3. **`lint` does not match its own manifest name.** The marketplace calls it `lint`, but `plugins/lint/.claude-plugin/plugin.json` says `"name": "linter"`.
   - Codex refuses to install it: "plugin.json name `linter` does not match marketplace plugin name `lint`".
   - Claude Code installs it as `lint@acme-tools` but displays it as `linter`, and `linter@acme-tools` is "not found". The validator does not flag this.

4. **Codex users never see `notes`.** Codex 0.157.1 leaves out entries with `"source": "github"`, with no warning. Removing `sha`, removing `ref`, or using just `{source: github, repo}` all still dropped it. A `"source": "url"` entry with the same `sha` does appear. Claude Code accepts the github form.

### Should fix

5. **`deploy` version mismatch.** The marketplace entry says `2.0.0`, but `plugin.json` says `1.9.0`, and both clients install 1.9.0. The Claude validator warns that the entry version is silently ignored.

6. **`remote-x` is not pinned.** It points to `https://github.com/acme/remote-x.git` at `ref: "main"` with no `sha`, so whatever is pushed to main is what users get. `notes` pins a `sha`, which is the pattern to copy.

7. **The two remote plugins were not audited.** I did not fetch `acme/notes` or `acme/remote-x`, so I can't confirm those repos exist or what they contain. Someone needs to review them before the announcement.

8. **The skills are empty stubs.** Every `SKILL.md` body just repeats its description, with no commands, steps or checks.
   - `fmt` and `lint` don't say which tools or settings "the team's style" means.
   - `deploy` gives no target, procedure, confirmation step or rollback for a staging deploy.
   - Installed, they fire on requests but give the agent nothing to act on.

### Minor

9. **The README is one line.** It says "For Claude Code and Codex users" but has no install commands for either client and no list of the plugins.

10. **Descriptions differ between the marketplace and `plugin.json`.**
    - guard: "with a pre-tool hook" in the marketplace vs "before the agent runs them" in `plugin.json`.
    - fmt and ok-tools: capitalisation differs (Python/python, Markdown/markdown).

11. **Metadata is thin, and the validator won't catch it.** The owner has no email or URL, and the plugins have no license, repository or homepage. `--strict` did not warn about any of these.

12. **`ok-tools` is a vague name** for a Markdown table and heading formatter.

A caution for CI: the Claude validator alone would miss findings 2, 3 and 4. If you gate on it, also run `codex plugin list --json --available` against the marketplace and compare the result with the entry list.
