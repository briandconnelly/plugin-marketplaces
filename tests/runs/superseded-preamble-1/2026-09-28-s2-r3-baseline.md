## Final report

I added `lint-kit` to both marketplace catalogs in the repo. The changes are not committed.

**Changes**
- `$RUN/repo/.claude-plugin/marketplace.json` (Claude Code): new entry `{"name": "lint-kit", "source": "./plugins/lint-kit", "description": "lint-kit"}`.
  The description is just the plugin name because every existing entry does the same.
- `$RUN/repo/.agents/plugins/marketplace.json` (Codex): new entry with a local path source, `AVAILABLE`/`ON_INSTALL` policy and the `Developer Tools` category, matching the other entries.

The repo has a separate catalog for each tool. `README.md` only lists plugins that are limited to one tool (`claude-hooks` for Claude Code, `codex-helper` for Codex), and `lint-kit` isn't one of them. So I listed it in both, the same way as `alpha-notes` and `branch-tidy`, and left the README as it was. In both files the new entry sorts alphabetically at the end.

**Checks**
- `claude plugin validate .` passed for the Claude marketplace, and `claude plugin validate plugins/lint-kit` passed for the plugin. I ran both against a throwaway config directory in `.tool-homes/` and deleted it afterwards.
- To make sure the validator can fail, I also ran it on a deliberately malformed marketplace, and it rejected it.
- I found no Codex command that validates a marketplace offline, so the Codex file is only confirmed to be valid JSON. Whether Codex will accept the entry has not been tested.

**For you to check**
- `lint-kit` has two manifests that disagree on version. `plugins/lint-kit/plugin.json` says 1.1.0, and `plugins/lint-kit/.claude-plugin/plugin.json` says 1.0.0.
- Claude Code reads the `.claude-plugin` one, so Claude users will see 1.0.0. I couldn't confirm which one Codex reads.
- The catalog entries don't include a version, so I left both files alone. You'll probably want to bring them in line, or remove the stray one at the plugin root.
