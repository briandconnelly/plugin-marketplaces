## Final report

I audited the acme-tools marketplace at $RUN/repo and it isn't ready to announce. Of the 7 listed plugins, only `ok-tools` and `deploy` install and load cleanly on both hosts. `guard` also installs on both but provides no hooks on either.

**How I checked:** I used Claude Code 2.1.284 and codex-cli 0.157.1, both with throwaway config directories under `.tool-homes/`. In each I added the marketplace from its local path, listed its plugins and installed the local ones. I also ran `claude plugin validate`, normal and `--strict`, on the marketplace and on each plugin. For some questions I tested changed scratch copies of the files. No models were called and nothing on a remote was contacted, so the two remote plugins were never fetched. Afterwards I deleted `.tool-homes/`; `git status` shows a clean tree. I changed no repo files.

### Blocking
1. **`fmt` fails on both hosts.** Its entry uses `"source": "plugins/fmt"`, with no leading `./`.
   - Claude: `validate` exits 1 with `plugins.2.source: Invalid input`, and install fails with "marketplace entry is invalid". `marketplace add` still reports success, so users only find out when they install.
   - Codex: the plugin is silently left out of `plugin list`, with no warning, and `plugin add fmt@acme-tools` says "not found". Changing it to `./plugins/fmt` fixed it on both hosts.
2. **`notes` is invisible in Codex.** Codex silently drops the `{"source":"github","repo":...}` form, with or without `sha`/`ref`. Rewritten as `{"source":"url","url":"https://github.com/acme/notes.git","ref":"v2.0.0","sha":"3add7b96..."}`, the entry shows up in Codex with its sha kept, and Claude's validator raises no error on it. It works in Claude as written.
3. **`guard` blocks nothing on either host.**
   - The marketplace entry sets `"hooks": "./hooks/hooks.json"`. Claude installs it but `plugin list` shows "✘ failed to load" with "the file-path and array forms are not yet supported in a marketplace entry".
   - There is no `hooks/` directory in `plugins/guard` anyway. `claude plugin details` reports Hooks (0).
   - The only thing it ships is a one-line skill that restates "block risky shell commands". The listing ("Block risky shell commands with a pre-tool hook") advertises protection that doesn't exist, which is worse than no plugin. `claude plugin validate` does not catch this.
4. **`lint` fails in Codex because its names don't match.** The entry name is `lint`, but `plugins/lint/.claude-plugin/plugin.json` and the skill directory are named `linter`.
   - Codex: `plugin add lint@acme-tools` fails with "plugin.json name `linter` does not match marketplace plugin name `lint`", even though `plugin list` shows it as available.
   - Claude: it installs as `lint@acme-tools`, but `details` shows it as `linter`, so users see two names.

### Should fix
5. **`deploy` version mismatch.** The entry says `"version": "2.0.0"` but `plugin.json` says `1.9.0`. Both hosts install 1.9.0, and Claude's validator warns that the entry version is silently ignored. `validate --strict` fails on this alone.
6. **`remote-x` is not pinned.** It uses `"ref": "main"` with no `sha`, so what users get changes whenever that branch moves. Pin a tag and sha the way `notes` does. I did not check that `acme/remote-x` or `acme/notes@v2.0.0`/that sha exist.
7. **The skills are one-line stubs.** Each SKILL.md body just repeats its description, e.g. `plugins/deploy/skills/deploy/SKILL.md` is only "Deploy a service to the staging environment."
   - None has actual instructions: which linters, which formatter settings, which deploy target, or any confirmation steps.
   - `deploy` is a skill the model can start on its own and has no guardrails.

### Minor
8. **Descriptions differ** between the marketplace entry and `plugin.json`:
   - capitalisation: `fmt` ("python/typescript") and `ok-tools` ("markdown");
   - wording: `guard` ("with a pre-tool hook" vs "before the agent runs them").
   Claude shows the marketplace text.
9. **`ok-tools` is a vague name** for a Markdown-table and heading formatter.
10. **README.md is three lines.** It says who the marketplace is for but gives no install commands for either host, no plugin list, no license and no support contact. There is no LICENSE file, and `owner` has only a name.

Codex reads `.claude-plugin/marketplace.json` and `.claude-plugin/plugin.json` directly, so you don't need separate Codex manifests. But Codex drops unsupported entries silently: always run `codex plugin list -m acme-tools --available --json` and compare it with the 7 entries you expect. Claude's `validate` exits 0 on `guard`, so it missed the load failure and the missing hooks; only an actual install and `claude plugin list` showed them.
