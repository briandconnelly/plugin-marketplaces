## Final report

## Audit of the acme-tools marketplace

I didn't change any repo files. I used Claude Code 2.1.284 and Codex CLI 0.157.1 locally, each with throwaway config under `.tool-homes/`, which I deleted afterward, so `git status` is clean. The checks I ran:
- `claude plugin validate` and `validate --strict`.
- `claude plugin marketplace add`, `install`, `list` and `details`.
- `codex plugin marketplace add`, `list --json --available` and `add`.
- Codex listings of edited scratch copies, to find out why two entries go missing.

No model was prompted and nothing was fetched from GitHub.

Of the 7 plugins in `.claude-plugin/marketplace.json`, Claude Code lists all 7 and Codex lists only 5. The Claude Code check is `claude plugin validate`, which currently exits 1.

### Blockers

1. **`fmt` is broken in both tools.** Its entry uses `"source": "plugins/fmt"` without the leading `./`.
   - `claude plugin validate` fails with `plugins.2.source: Invalid input`.
   - `claude plugin install fmt@acme-tools` fails with the same error.
   - Codex silently leaves `fmt` out of `plugin list`, and `codex plugin add` reports "not found". Changing it to `./plugins/fmt` made it appear in a scratch copy.

2. **`guard` has no hook, so it doesn't block anything.** Its entry says `"hooks": "./hooks/hooks.json"`, but `plugins/guard/` contains only `.claude-plugin/` and `skills/`.
   - **Claude Code:** the install reports success, but `plugin list` then shows `✘ failed to load: Hook load failed: hooks: the file-path and array forms are not yet supported in a marketplace entry…`. `plugin details` shows Hooks (0) while still describing it as "Block risky shell commands with a pre-tool hook".
   - **Codex:** installs it as "installed, enabled" with no warning and no hook.
   - `claude plugin validate` passed this plugin and did not catch it.
   - For a security plugin, that means it fails open: users think commands are guarded when they aren't. The hook needs to go in `plugins/guard/hooks/hooks.json` (or its `plugin.json`), and the marketplace-entry `hooks` field should be removed.

3. **`lint` is named `linter` in its own manifest and fails on Codex.** The entry is named `lint` but `plugins/lint/.claude-plugin/plugin.json` says `"name": "linter"`.
   - **Codex:** `codex plugin add lint@acme-tools` fails with `plugin.json name 'linter' does not match marketplace plugin name 'lint'`.
   - **Claude Code:** installs it as `lint@acme-tools`, but `details` shows it as `linter`.
   - The validator didn't flag this either. Pick one name for the entry, `plugin.json` and ideally the skill.

4. **`notes` is invisible to Codex.** Codex 0.157.1 drops `"source": "github"` entries without any message.
   - Removing `sha` or `ref` in scratch copies didn't bring it back.
   - Rewriting it as `{"source":"url","url":"https://github.com/acme/notes.git","ref":"v2.0.0","sha":"…"}` made it list correctly.
   - Claude Code accepts the github form. I couldn't check that `acme/notes` at `v2.0.0` / `3add7b9…` exists without contacting GitHub.

5. **Codex install support rests on Claude-format files, and the README doesn't explain how to install.** There is no Codex-native manifest (`.codex-plugin/plugin.json` or `.agents/plugins/marketplace.json`). Codex does read `.claude-plugin/marketplace.json` and the plugins' `.claude-plugin/plugin.json`, but with items 1, 3 and 4 only ok-tools, deploy and remote-x (not tested) install cleanly there, plus guard with no hook. `README.md` says "For Claude Code and Codex users" but gives no install commands for either.

### Should fix

6. **`remote-x` points at a moving branch.** It uses `"ref": "main"` with no `sha`, so every user gets whatever is on `main` when they install, and the contents can change with no review. `notes` is pinned by sha; `remote-x` should be too. I didn't fetch it, so its contents are unaudited.

7. **`deploy` versions disagree.** The entry says `2.0.0` and `plugin.json` says `1.9.0`. Claude warns that plugin.json wins and the entry version is ignored. Both tools installed 1.9.0, so the advertised 2.0.0 isn't what ships.

8. **The skills contain no instructions.** Every `SKILL.md` body just repeats its description in one line.
   - **deploy:** has no target, no procedure and no confirmation step, yet the model is free to trigger it. The agent would improvise a staging deploy. Add real steps, and consider `disable-model-invocation: true` so it runs only when a user asks.
   - **guard:** a skill can't block commands; that only works through a hook (item 2).
   - **fmt and lint:** they don't say which formatters or linters to run, or what "the team's style" is.

### Minor

9. **Descriptions drift between files.** The marketplace entries and `plugin.json` differ in capitalisation (Markdown/markdown, Python/python) and, for guard, in wording ("with a pre-tool hook" vs "before the agent runs them"). Claude shows the marketplace entry's text.
10. **Missing basics.** There is no LICENSE file, no contact email or URL for the owner, and no release tags. The repo has one commit ("fixture s6") on `master`.
11. **The validator isn't enough as a release gate.** It missed items 2 and 3, which only showed up in real installs. Before announcing, run an install in both tools (`claude plugin install` + `plugin list`, and `codex plugin list --available` + `codex plugin add`) for every entry, alongside `claude plugin validate --strict .`.

**Not verified:** whether `notes` and `remote-x` exist and what they contain (that needs GitHub access), and whether the skills actually trigger (that needs a model run).
