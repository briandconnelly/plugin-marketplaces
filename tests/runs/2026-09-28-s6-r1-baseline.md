## Final report

I audited the acme-tools marketplace, and I wouldn't announce it yet. Of the seven plugins, only `ok-tools` and `deploy` install cleanly for both Claude Code and Codex, and `deploy` has no real instructions. I changed no tracked files (`git status` is clean).

**How I checked:** I ran Claude Code 2.1.284 (`claude plugin validate`, `marketplace add`, `install`, `list`, `details`) and Codex 0.157.1 (`plugin marketplace add`, `plugin add`). Each ran against fresh configuration under `$RUN/repo/.tool-homes/`. A scratch copy there (`.tool-homes/scratch`) was used to confirm fixes. I sent no prompts to any model and made no network calls, so `notes` and `remote-x` (fetched from GitHub) were not install-tested.

**Blockers**

1. **`guard` doesn't block anything, on either tool.** It is advertised as "Block risky shell commands with a pre-tool hook". Its marketplace entry has `"hooks": "./hooks/hooks.json"`, but that file doesn't exist and the plugin contains only a one-line skill.
   - Claude Code installs it, then `plugin list` shows `✘ failed to load` with "Hook load failed: … the file-path and array forms are not yet supported in a marketplace entry." `plugin details` shows Hooks (0).
   - Codex installs it with no error and no hook — only `.claude-plugin/plugin.json` and `skills/guard/SKILL.md` land in the cache.
   - Users would think they are protected when they aren't. `validate` passes the plugin directory; the marketplace run stopped at the `fmt` error, and after fixing that it reported only the `deploy` version warning.
   - Two smaller mismatches: its `plugin.json` description ("…before the agent runs them") differs from the marketplace entry ("…with a pre-tool hook"). The skill tells the model to "block" commands, which a skill can't enforce.

2. **`fmt` can't be installed on either tool.** Its source is `"plugins/fmt"`, without the leading `./` (`.claude-plugin/marketplace.json`, the third entry).
   - `claude plugin validate` fails with `plugins.2.source: Invalid input`.
   - `marketplace add` still succeeds, so the problem is hidden until install: `claude plugin install fmt@acme-tools` fails with "marketplace entry is invalid: source: Invalid input".
   - Codex silently drops the entry: "plugin `fmt` was not found in marketplace `acme-tools`".
   - Changing it to `./plugins/fmt` in the scratch copy made it install on both tools.

3. **`lint` fails on Codex and is confusing on Claude Code.** The marketplace calls it `lint`, but `plugins/lint/.claude-plugin/plugin.json` and the skill are named `linter`.
   - Codex refuses it: "plugin.json name `linter` does not match marketplace plugin name `lint`".
   - Claude Code installs it as `lint@acme-tools`, but `details` shows the plugin as `linter`, and `install linter@acme-tools` fails with "not found". So users see two names.
   - The validator doesn't flag this.

4. **Nothing in the repo is written for Codex specifically.** The README says "For Claude Code and Codex users", but there's no Codex manifest; Codex reads `.claude-plugin/marketplace.json` and each plugin's `.claude-plugin/plugin.json`. The result is findings 1–3: one plugin silently missing, one refused, one installed without its safety feature. I did not check Codex's documented plugin layout, so I can't say whether Codex manifests would change any of this — worth checking before promising Codex support. Codex handling of the GitHub/URL sources is also untested.

**Should fix**

5. **Four of the five local skills are empty.** `deploy`, `fmt`, `lint`/`linter` and `guard` each just repeat their description. No commands, services, environments, safety checks or "team style" are defined, so the agent will make them up. That is most risky for `deploy`, which is a live deploy with no procedure or confirmation step. Only `ok-tools` has real instructions.

6. **`deploy` shows two different versions.** The marketplace entry says `"version": "2.0.0"`; `plugins/deploy/.claude-plugin/plugin.json` says `1.9.0`. Claude Code's validator warns that `plugin.json` wins and the entry is ignored, and both tools installed 1.9.0. Users browsing the marketplace see 2.0.0.

7. **`remote-x` follows a moving branch.** Its source is a URL with `"ref": "main"` and no commit hash, so what users install can change without notice. `notes` is pinned (`ref` v2.0.0 plus a `sha`), but I couldn't confirm the tag matches that hash without network access.

**Minor**

8. The README has no install steps for either tool, no plugin list, no license and no contact details. The marketplace owner has only a name.
9. The name `ok-tools` doesn't say what it does (formatting Markdown tables and headings).
10. `plugins/fmt/skills/fmt/SKILL.md` lowercases "python and typescript" in its body.

**Suggested gate:** run `claude plugin validate --strict` in CI. It would have caught findings 2 and 6, but not 1 or 3. For those, try installing on both tools from a clean configuration, as above, and check that no plugin shows "failed to load".
