## How the reruns got here

The first batches ran under preamble v1 (the text plan 2b's Task 6 wrote); their 18 records are kept in `tests/runs/superseded-preamble-1/`.
Six of their runs were discarded: four for writing into the dispatching session's scratch directory, which Claude Code names to every subagent as the place for temporary files, one (s6-r4) for creating `/tmp/nul`, and one (s1-r3) for writing a `url.insteadOf` section into the owner's real `~/.config/git/config` by changing `HOME` while `XDG_CONFIG_HOME` still pointed at the real configuration.
The owner then chose to add two preamble lines (temporary files only under `WORKDIR/.tool-homes/`; `XDG_CONFIG_HOME` alongside `HOME`) and to rerun every scenario, and the s6 fixture was fixed at the same time (see below), so every result above comes from preamble v2 and the current fixture trees.
Under preamble v2, one of 22 runs was discarded: s1-r1 ran git with the real user configuration through a quoting mistake and tried to clone `github.com/acme/weather-mcp`, which was refused.

Six tooling defects found during the runs were fixed test-first before later runs were collected: non-transcript files in the task directory, the scratch path leaking into records, `$HOME` expanded to the real home after an arm reassigned it, diffs taken against `HEAD` instead of the fixture tree, read-only git listings flagged as writes, and a task-output file vanishing mid-listing; each fix and its test is in the branch history.

## Failures and costs the skill can address

- **Not naming what was left unchecked (s2 criterion 5 ×2, s5 criterion 6 ×3).**
  Arms list what they ran and stop; s5-r2's report names only "Both still parsed as valid JSON" and says nothing about the Claude Code, Codex, or Copilot checks it skipped.
  Address in SKILL.md R12 and `validation.md` (report skipped and inconclusive checks as such).
- **Flagging a version disagreement without reconciling it (s2 criterion 4 ×3).**
  Every s2 arm found that lint-kit's `.claude-plugin/plugin.json` (1.0.0) and portable root `plugin.json` (1.1.0) disagree and that Codex installs 1.1.0 while Claude Code installs 1.0.0, then added the entries anyway: "I didn't change either one because I can't tell which is correct" (s2-r2).
  Address in R6 and R7, `releases.md` (one version value, set in every field each reader reads), and `multi-tool.md` (which manifest each tool reads).
- **Rediscovering tool behaviour by trial (cost: s4, s1, s3).**
  s4 arms spent 51 to 78 calls establishing that Codex does not expand `${CLAUDE_PLUGIN_ROOT}` in an MCP `command`, that Copilot prefers a plugin's root `.mcp.json` over the one its manifest names, and that Copilot passes `${user_config.*}` through unexpanded; s1 arms rebuilt the same facts with argv-recording stand-in servers.
  Address in `codex.md`, `copilot-cli.md`, and `feature-matrix.md`, each fact with provenance, so an agent can cite rather than probe.
- **Unsafe probing.**
  Preamble-v1 arms wrote into the session scratch directory and one wrote the owner's real git configuration; a preamble-v2 arm ran git with the real configuration and contacted GitHub.
  The arms that stayed isolated converged on a method worth teaching: `HOME`, `XDG_CONFIG_HOME`, and each tool's configuration variable under the working directory; a throwaway `GIT_CONFIG_GLOBAL` with `insteadOf` rules pointing remote URLs at a local mirror; and a network-denying sandbox (`sandbox-exec` on macOS) around tool CLIs.
  Address in R15 and `validation.md` (the safe probing method, including that `COPILOT_HOME` does not isolate sign-in and that version and help calls to Codex write temporary state into the real `CODEX_HOME`).
- **Audit findings that are opinions (s6 criterion 8 ×3).**
  Every s6 arm reported that the name `ok-tools` "doesn't say what it does" alongside the real defects; s6-r1 also reported Codex's handling of `notes` as untested rather than observing that Codex drops it (criterion 2).
  Address in the audit workflow in SKILL.md: separate defects that change what a tool loads from naming and style suggestions.
- **Design choice still split.**
  Two of three s3 arms wrote both native catalogs and one wrote a single `.claude-plugin/marketplace.json` that Codex reads as a fallback; all three s1 arms wrote both.
  Address in SKILL.md's default (spec §2: separate native catalogs, parity-checked) with its reason.

## Facts observed by the arms (candidates for the references)

Each needs its own provenance entry before it enters a reference; archived tool output is in `tests/runs/evidence/` where named.

- Codex silently drops catalog entries whose source is `github`, with or without `ref` and `sha`, and lists the same entry as a `url` or `git-subdir` source (s7-r3 call 9, archived).
- Codex refuses an install whose manifest `name` differs from the catalog entry: "plugin.json name `linter` does not match marketplace plugin name `lint`" (s6-r2 call 8, archived).
- Claude Code installs a plugin whose catalog entry sets `hooks` to a path, then reports it as failed to load: "the file-path and array forms are not yet supported in a marketplace entry"; `claude plugin validate` does not flag it (s6-r2 call 11, archived).
- Codex starts a plugin MCP server with `${CLAUDE_PLUGIN_ROOT}` unexpanded in its arguments (s1-r2 call 22, archived; also s1-r3 and s4-r1).
- Codex converts a Claude Code plugin command into a skill named `source-command-review` on install (s4-r1 call 13, archived; consistent with `docs/research/2026-09-28-codex-command-migration-probe.md`).
- When a plugin has both a portable root `plugin.json` and `.claude-plugin/plugin.json`, Codex installs the root manifest's version (s2-r3 call 7, archived).
- A change pushed without a version bump is not delivered to Claude Code users ("already at the latest version"), while `codex plugin marketplace upgrade` refreshed the installed copy in place in two runs (s3-r2 call 19, archived; s3-r1 report); s3-r3 instead saw the installed copy unchanged until `codex plugin add` was rerun, so this needs a controlled probe.
- Copilot CLI passes `${user_config.api_key}` to a plugin's MCP server as literal text and reads the plugin's root `.mcp.json` in preference to the MCP file its manifest names (s4-r2 call 31, archived; s4-r1 report).
- `claude plugin validate` passes with a warning when a catalog entry's version differs from its manifest, and `--strict` fails on the same input (all s7 runs; objective checks).
- `codex app-server` attempts an unauthenticated connection to `api.openai.com` at startup and fetches Codex's built-in plugin catalog (s4-r1 report; not archived).

## Isolation

- Snapshots of `~/.codex`, `~/.copilot`, and `~/.claude/plugins` before and after every batch showed only files written by a running Codex app-server daemon (logs, model cache) and temporary state from exempt `codex --version` and `--help` calls; no plugin or marketplace file changed.
- The owner's `~/.config/git/config` still holds the section preamble-v1 s1-r3 wrote (lines 38 to 39, pointing at a scratch path); the executor did not remove it because the arm's own removal was denied by the permission system, and the owner has been told how to remove it.
- One arm created an empty `/tmp/nul` (preamble-v1 s6-r4, discarded).
- Confounds: the dispatching session's auto-mode permission check blocked preamble-v2 s5-r2's commit of the pin move, so its hold was partly forced; the harness names its scratch directory to every subagent; and the session carried plugins including `plugin-dev`, which plan 2c's treatment arms will share.
- Rulings on reads of installed tool binaries, tool-initiated network traffic, and the harness's stored copies of an arm's own output are in each record's isolation note.
