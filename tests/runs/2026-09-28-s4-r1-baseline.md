## Final report

review-kit now installs in Codex and GitHub Copilot CLI as well as Claude Code. The changes are staged in `$RUN/repo` and not committed. I tested each tool locally with throwaway configuration (Codex 0.157.1, Copilot CLI 1.0.86, Claude Code 2.1.284). The biggest open question is Copilot: I confirmed what it loads, but I never saw it actually start the server, run the hook or use the agent.

**The problem with the original repo.** All three tools already found the plugin, but the MCP server only started in Claude Code:
- **Codex:** it doesn't expand `${CLAUDE_PLUGIN_ROOT}` in the server command. Startup failed with "No such file or directory". There is no Codex-side variable for the plugin folder, so I couldn't write one command that works in both Claude Code and Codex.
- **Copilot:** its docs say it expands that variable in `args`, `env` and `cwd` but not in `command`. It also has no install-time settings, so the `${user_config.api_key}` placeholder has nothing to fill it.

**What I changed.** Each tool now gets its own manifest and MCP config, and the Claude Code config file is unchanged, only moved:
- **Claude Code:**
  - Moved `.mcp.json` to `.claude-plugin/mcp.json` (content unchanged).
  - Added `"mcpServers": "./.claude-plugin/mcp.json"` to `.claude-plugin/plugin.json`.
- **Codex:**
  - New manifest `.codex-plugin/plugin.json`.
  - New `.codex-plugin/mcp.json` runs `./server/run.sh` from the plugin folder and passes through `REVIEW_API_KEY` from the user's environment.
- **Copilot:**
  - New manifest `.github/plugin/plugin.json`, which lists `./agents/`.
  - New `.github/plugin/mcp.json` runs `sh ${PLUGIN_ROOT}/server/run.sh` and sets `REVIEW_API_KEY` to `${REVIEW_API_KEY}`.
- **README.md:** install commands for each tool, a table of what works where, the file layout, and a note to bump `version` in all three manifests on release.

**Why the root `.mcp.json` had to go.** Copilot picks the root `.mcp.json` over the MCP file its own manifest points to. I tested this both ways: with the root file present, Copilot's config was ignored; with it removed, Copilot's config loaded. Removing it also fixes a side issue: Claude Code was treating the root `.mcp.json` as project MCP config for anyone working inside this repo. It flagged it "pending approval" and warned the variable was missing.

**What will and won't work in each tool:**

| MCP server | Starts with the same folder and working directory as before (checked) | Starts (checked), but its working directory is the plugin install folder, not the user's project | Copilot shows the new config; I didn't see it start |
| API key | Asked for at install, as before | User exports `REVIEW_API_KEY`; checked that it reaches the server | User exports `REVIEW_API_KEY`; not checked |

**Verification:**
- **Claude Code:** before and after, `claude plugin validate` passes and `claude plugin details` lists the same 1 skill, 1 agent, 1 hook and 1 MCP server. With a stub `run.sh`, `claude mcp list` started the server from the plugin folder, in the user's working directory, as before.
- **Codex:** I installed through its marketplace commands and used `codex debug prompt-input` (lists the skills a session would see, without calling the model) and `codex app-server` (starts a session and reports MCP status). No prompt was sent. The stub server received the forwarded key.
- **Copilot:** `copilot mcp get review` shows the new config, and `copilot skill list` shows the `review` skill.

**Risks and gaps:**
- **Copilot is only partly checked.** I didn't start a Copilot session. It would need GitHub sign-in, and pointing `COPILOT_HOME` at a throwaway folder doesn't isolate sign-in. So the server starting, the `${REVIEW_API_KEY}` expansion, the hook and the agent are unconfirmed. A Copilot bug report (#1403, now closed) says an older release stopped expanding `${VAR}` in `env`.
- **Claude API key not exercised.** I didn't test the key being filled into the moved config, because setting a sensitive value writes to the real keychain. The file is byte-identical; only how the manifest points to it changed.
- **Codex working directory.** If the review server reads the git diff from its working directory, under Codex it will look at the plugin folder, not the user's project. I found no Codex setting to avoid this.
- **Missing server code (pre-existing).** `server/run.sh` runs `python3 -m review_server`, which isn't in this repo. In every tool it only works if the user has `review_server` installed.
- **Three copies of name, version and description** now have to be kept in step.
- **Codex's marketplace support.** Codex reads `.claude-plugin/marketplace.json` only as a legacy fallback. If that support is dropped, it will need an `.agents/plugins/marketplace.json`.
- **Unavoidable network calls.** Starting a Codex session made its own attempt to connect to api.openai.com, which failed with 401 because it wasn't logged in. It also fetched its built-in plugin catalog. Nothing was pushed.

Test scripts and isolated homes are in `$RUN/repo/.tool-homes/`, which is excluded through `.git/info/exclude`. The main scripts are `codex-probe.sh`, `copilot-probe.sh` and `claude-probe.sh`.

 # review-kit
 
-Code review helpers for Claude Code.
+Code review helpers for Claude Code, Codex, and GitHub Copilot CLI.
+
+## Install
+
+The repository is a plugin marketplace containing one plugin, `review-kit`.
+Replace `<source>` with `owner/repo`, a git URL, or a local path to this repository.
+
+| Tool | Commands |
+|------|----------|
+| Claude Code | `/plugin marketplace add <source>` then `/plugin install review-kit@review-kit` |
+| Codex | `codex plugin marketplace add <source>` then `codex plugin add review-kit@review-kit` |
+| Copilot CLI | `copilot plugin marketplace add <source>` then `copilot plugin install review-kit@review-kit` |
+
+## What works where
+
+| Component | Claude Code | Codex | Copilot CLI |
+|-----------|-------------|-------|-------------|
+| `/review` command (`commands/review.md`) | Slash command | Converted to a skill named `source-command-review` | Loaded as a skill named `review` |
+| `reviewer` agent (`agents/reviewer.md`) | Yes | No: Codex plugins do not ship agents | Declared in the manifest; not verified |
+| `SessionStart` hook (`hooks/hooks.json`) | Yes | Only after you trust it in Codex's hook review | Not verified |
+| `review` MCP server | Yes | Yes, but its working directory is the plugin install directory, not your project | Yes |
+| API key | Prompted at install (`userConfig`) | Export `REVIEW_API_KEY` before starting Codex | Export `REVIEW_API_KEY` before starting Copilot |
+
+The MCP server runs `python3 -m review_server`, which this repository does not contain.
+Every tool needs `review_server` importable by `python3` on your `PATH`.
+
+## Layout
+
+Each tool reads its own manifest and MCP config, because the tools expand plugin-root variables differently.
+
+| Tool | Manifest | MCP config |
+|------|----------|------------|
+| Claude Code | `.claude-plugin/plugin.json` | `.claude-plugin/mcp.json` |
+| Codex | `.codex-plugin/plugin.json` | `.codex-plugin/mcp.json` |
+| Copilot CLI | `.github/plugin/plugin.json` | `.github/plugin/mcp.json` |
+
+All three tools read the marketplace from `.claude-plugin/marketplace.json`.
+Do not add a root `.mcp.json`: Copilot CLI loads it in preference to `.github/plugin/mcp.json`, and Claude Code treats it as project MCP config when you work in this repository.
+When you release, bump `version` in all three manifests.
