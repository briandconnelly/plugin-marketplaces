## Final report

The repo is now a plugin marketplace called `acme-agent-tools` that both Claude Code and Codex can add. It offers `hello-tools` and `weather-mcp`, pinned to `v1.3.0` at commit `bdee23e46e072243455f1ba83ce9d8e2d7584e0a`. Both plugins install in both tools. One problem: under Codex, weather-mcp's MCP server gets a start path that can't work, so it installs but won't run there. I haven't committed anything.

**What I added** (in `$RUN/repo`):
- **Claude Code catalog:** `$RUN/repo/.claude-plugin/marketplace.json`. `hello-tools` points at `./plugins/hello-tools`. `weather-mcp` points at the GitHub repo `acme/weather-mcp` with `ref: v1.3.0` and the commit `sha`, and Claude Code uses the `sha` when both are set.
- **Codex catalog:** `$RUN/repo/.agents/plugins/marketplace.json`. `hello-tools` points at the same local folder. `weather-mcp` points at `https://github.com/acme/weather-mcp.git` with the same `ref` and `sha`. Each entry has the `policy` and `category` fields Codex's docs say to include.
- **README:** `$RUN/repo/README.md` now has install commands for both tools and a note to keep the two catalogs in step. It also describes the Codex problem below.
- **Unchanged:** the `hello-tools` plugin itself. Codex already reads its existing Claude-style `.claude-plugin/plugin.json` and `.mcp.json`.

**How I checked it:** every tool ran with throwaway home and config directories under `.tool-homes/`, and nothing was sent to a model. I didn't contact github.com/acme, so the tests pointed `weather-mcp` at the local mirror instead. Only that URL changed; the ref and sha were the same.
- **Validation:** `claude plugin validate` passed on the marketplace and on `hello-tools`. To confirm it can fail, I ran it on a copy with a `..` path, and it failed with exit code 1.
- **Claude Code 2.1.284:** I added the marketplace and installed both plugins, and both show as enabled. The mirror's newest tag is `v1.4.0`, but the installed copy is 1.3.0 at commit `bdee23e…`. `claude plugin details` lists `hello-tools` with 1 skill and the `hello` server, and `weather-mcp` with the `weather` server.
- **Codex 0.157.1:** I added the marketplace; Codex picked up `.agents/plugins/marketplace.json` and read the ref and sha. Both plugins installed; the `weather-mcp` copy is at commit `bdee23e…` and its `server.py` is version 1.3.0. `codex mcp list` shows both MCP servers. Codex's local app-server (a background process that sends no prompts) found the `hello-tools:hello-tools` skill.
- **Not tested:** whether the MCP servers actually run in Claude Code. The README says Claude Code expands `${CLAUDE_PLUGIN_ROOT}`; that comes from its documentation, and I didn't check it.

**The Codex problem:** weather-mcp v1.3.0 starts its server with `python3 ${CLAUDE_PLUGIN_ROOT}/server.py`. I installed a small test plugin into Codex that records what it receives at startup. Codex passed `${CLAUDE_PLUGIN_ROOT}` through as literal text, didn't set it as an environment variable, and started the server in the directory Codex was launched from. So the `weather` server installs but can't find `server.py` under Codex. The marketplace can't fix this without changing the upstream release. It needs a weather-mcp release that starts the server in a way Codex supports, or a fork you pin to instead. Which way to go is your call.

**Also note:** in my first test run, a config setting I used to switch off `hello-tools` didn't take effect. Codex tried to start its server (`uvx hello-mcp==0.3.0`), which may have reached PyPI. The startup failed. The later runs switched it off properly.

The test copies and throwaway homes are in `.tool-homes/`, which this repo's `.git/info/exclude` already ignores.

 # acme-agent-tools
 
 Plugins our team uses with coding agents.
+
+## Install
+
+This repository is a plugin marketplace named `acme-agent-tools` for Claude Code and Codex.
+
+| Plugin | Source |
+| --- | --- |
+| `hello-tools` | `plugins/hello-tools` in this repository |
+| `weather-mcp` | [acme/weather-mcp](https://github.com/acme/weather-mcp) at `v1.3.0`, pinned to commit `bdee23e46e072243455f1ba83ce9d8e2d7584e0a` |
+
+Claude Code reads `.claude-plugin/marketplace.json`:
+
+```bash
+claude plugin marketplace add <owner>/<this-repo>
+claude plugin install hello-tools@acme-agent-tools
+claude plugin install weather-mcp@acme-agent-tools
+```
+
+Codex reads `.agents/plugins/marketplace.json`:
+
+```bash
+codex plugin marketplace add <owner>/<this-repo>
+codex plugin add hello-tools@acme-agent-tools
+codex plugin add weather-mcp@acme-agent-tools
+```
+
+Keep the two catalogs in step: when you add a plugin or bump the `weather-mcp` pin, update both files.
+
+Known limitation: `weather-mcp` v1.3.0 starts its MCP server with `${CLAUDE_PLUGIN_ROOT}/server.py`.
+Codex CLI 0.157.1 passes that string to the server unexpanded, so the `weather` MCP server installs but does not start under Codex.
+Claude Code expands that variable for plugin MCP servers.
