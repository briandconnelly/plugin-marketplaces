## Final report

I added `lint-kit` to both marketplace catalogs; the Claude Code one passes its validator. Nothing is committed and nothing was pushed.

**Changes (in `$RUN/repo`):**
- `.claude-plugin/marketplace.json` (Claude Code): new entry `{"name": "lint-kit", "source": "./plugins/lint-kit", "description": "lint-kit"}`, in the same form as the existing entries.
- `.agents/plugins/marketplace.json` (Codex): new entry with a local source at `./plugins/lint-kit`, the same `AVAILABLE`/`ON_INSTALL` policy as the others, and category "Developer Tools".

**Why both catalogs:** the README lists only two exceptions, `claude-hooks` (Claude Code only) and `codex-helper` (Codex only). The other plugins, `alpha-notes` and `branch-tidy`, are in both catalogs. `lint-kit` is a single plain skill with no platform-specific part, so it follows the default, and the README needs no new note.

**Checks run:**
- Both files parse as JSON, and every `source` path in both catalogs points to a directory that exists.
- `claude plugin validate .` (the marketplace) and `claude plugin validate plugins/lint-kit` both passed. They ran with `HOME`, `XDG_CONFIG_HOME` and `CLAUDE_CONFIG_DIR` pointed at `.tool-homes/claude`.
- To show the validator can fail, I ran it on a copy under `.tool-homes/broken` with one entry missing its `source`. It reported `plugins.4.source: Invalid input`.
- I did not validate the Codex catalog with Codex itself. The only check on it is that it parses, its paths exist, and it matches the existing entries.

**For you to decide:**
1. **Version mismatch in lint-kit:** `plugins/lint-kit/.claude-plugin/plugin.json` says `1.0.0`, but a second manifest, `plugins/lint-kit/plugin.json`, says `1.1.0`. That second file uses an `agent-plugins.org` schema, and no other plugin in the repo has one. Neither marketplace entry records a version, so this didn't block the listing, but someone should decide which version is right and whether that extra file should stay.
2. **No Codex manifest in lint-kit:** it has no `.codex-plugin/plugin.json`, which is also true of `alpha-notes` and `branch-tidy`, both already in the Codex catalog. I kept to that pattern, but I haven't confirmed that Codex loads a plugin that only has a `.claude-plugin` manifest.
