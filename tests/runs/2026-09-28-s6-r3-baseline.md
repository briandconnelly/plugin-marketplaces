## Final report

I audited the acme-tools marketplace. It is not ready to announce. On Claude Code, 1 of 7 plugins won't install and 1 installs but fails to load. On Codex, 2 are silently missing from the list and 1 more won't install. The guard plugin doesn't block anything on either tool.

No repo files were changed; `git status` is clean. I ran real validate, marketplace-add and install commands against throwaway configs under `$RUN/repo/.tool-homes/`, using Claude Code 2.1.284 and codex-cli 0.157.1. I installed only the local plugins. I didn't fetch notes or remote-x, sent no prompts to any model, and contacted no remote service. Trial fixes were made on a scratch copy only (`.tool-homes/copy`).

All paths below are relative to `$RUN/repo`.

**Blockers**

1. **fmt is broken on both tools.** In `.claude-plugin/marketplace.json` its source is `"plugins/fmt"`, without the leading `./`.
   - Claude `claude plugin validate` fails with `plugins.2.source: Invalid input`, and `claude plugin install fmt@acme-tools` fails with the same error.
   - Codex leaves fmt out of `codex plugin list` with no warning; `codex plugin add fmt@acme-tools` says "not found in marketplace".
   - On the scratch copy, changing it to `"./plugins/fmt"` fixed both tools.

2. **guard doesn't guard anything.** It is advertised as "Block risky shell commands with a pre-tool hook", but it contains only a skill (`plugins/guard/skills/guard/SKILL.md`). There is no hook.
   - The marketplace entry has `"hooks": "./hooks/hooks.json"`, but `plugins/guard/hooks/` doesn't exist.
   - Claude: install reports success, then `claude plugin list` shows `✘ failed to load` with "the file-path and array forms are not yet supported in a marketplace entry". `claude plugin details` shows Hooks (0).
   - Codex: installs and enables it with no error, and the hooks field is silently ignored.
   - Users would believe risky commands are blocked when nothing is enforced. This matters most because it's the safety plugin.
   - Neither `claude plugin validate` nor `--strict` catches this; only the install does.
   - Its two descriptions also disagree ("with a pre-tool hook" in the marketplace vs "before the agent runs them" in `plugins/guard/.claude-plugin/plugin.json`).

3. **lint has a name mismatch.** The marketplace entry is `lint`, but `plugins/lint/.claude-plugin/plugin.json` says `"linter"`.
   - Codex: `codex plugin add lint@acme-tools` fails with "plugin.json name `linter` does not match marketplace plugin name `lint`".
   - Claude: installs as `lint@acme-tools` but displays as `linter`. The validator doesn't flag it, even with `--strict`.

4. **notes doesn't exist for Codex users.** It uses `"source": "github"`, which Codex silently drops.
   - On the scratch copy, Codex dropped `github` sources with and without `ref`/`sha`.
   - Rewriting it as `{"source":"url","url":"https://github.com/acme/notes.git","ref":"v2.0.0","sha":"3add7b96…"}` listed on Codex and passed Claude validation.
   - I couldn't check that the sha really is tag v2.0.0 without contacting GitHub; that's still to confirm.

**Should fix**

5. **remote-x isn't pinned.** It uses `"ref": "main"` with no `sha`, so every install or update pulls whatever is on main and the marketplace can't vouch for what users get. Pin a `sha` the way notes does. I didn't inspect its contents (remote).

6. **deploy's version is wrong.** The marketplace says `"2.0.0"`, `plugins/deploy/.claude-plugin/plugin.json` says `"1.9.0"`. Both tools install 1.9.0, and the Claude validator warns that the entry version is silently ignored (a hard failure under `--strict`).

7. **Four skills are empty shells.** The fmt, lint, deploy and guard `SKILL.md` files just repeat the description in one line. They name no linters, formatter settings, deploy command, target service or definition of "risky". So the agent has to improvise. For deploy that means unguided changes to a real environment, with no confirm-first step or rollback.
   - ok-tools is the only real skill (`plugins/ok-tools/skills/ok-tools/SKILL.md`); it has concrete, checkable steps.

**Minor**

8. `README.md` says "For Claude Code and Codex users" but has no install commands, plugin list or notes on differences between the two tools.
9. The name ok-tools doesn't say what it does (formatting Markdown tables and headings).
10. The owner entry has no contact (email or URL); this is optional for both tools.

**What passes:** ok-tools installs and enables cleanly on both. deploy installs on both (as 1.9.0). Codex reads `.claude-plugin/marketplace.json` directly, so no separate Codex manifest is needed once the issues above are fixed.

**How to catch these:** `claude plugin validate` catches only #1 and #6 in the committed marketplace. #2, #3 and #4 showed up only on real installs or in Codex's list. Before announcing, run the local install on both tools after fixing, not just the validator.
