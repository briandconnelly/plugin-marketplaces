## The refinement round

Plan 2c, Task 10, owed one round because s1 regressed in two of three runs.
Commit `dcb0609` changed SKILL.md and three references:

- the create workflow keeps every plugin the request names in every catalog it names and reports per-tool limits, instead of dropping an entry the user asked for (s1-r1 and s1-r2 had left weather-mcp out of the Codex catalog because its MCP server cannot start there);
- `multi-tool.md` states that a portable root `plugin.json` stops Codex and Copilot CLI from reading `commands/`, and how to convert a command so every tool keeps it (s4-r2, s4-r5);
- `claude-code.md` and `feature-matrix.md` state precisely how Claude Code handles an entry whose name differs from its manifest (s6-r3 found the earlier wording inexact);
- `validation.md` states that `codex debug prompt-input` starts MCP servers but not hooks, and that Copilot CLI's plugin, skill, and mcp subcommands open no session.

s1 and s4 were re-run with the refined skill (skill tree `6578ee9`); the other scenarios ran only with the first skill (`8fbcb38`).
The refinement also changed facts s2 and s6 arms rely on (how Claude Code handles an entry-name mismatch, and the `prompt-input` and Copilot lines in `validation.md`), so the skill as shipped is unmeasured on s2, s3, s5, s6, and s7.
The final review's fixes (commit after `6f6d20f`) then made the command-conversion advice in `multi-tool.md` a proposal for the user rather than a step, and narrowed two `validation.md` lines, after the s4 re-runs; those changes are unmeasured on s4 too.

## Findings left open

- Several s4 reports state behaviour taken from the references without saying so (criterion 5 in three runs); SKILL.md's port workflow already asks for a citation per claim, so the next change is probably a report template in `validation.md`.
- Three s4 arms read the references as saying Copilot CLI expands `${PLUGIN_ROOT}` in server arguments at launch; after the Codex review of PR #4, `copilot-cli.md` and `multi-tool.md` now say the arguments are shown unexpanded and their expansion at launch was not observed.
- The s4 fixture's `server/run.sh` runs a `review_server` module the fixture does not ship; every arm reported it, and it does not affect scoring.

## Isolation

- Home snapshots of `~/.codex`, `~/.copilot`, and `~/.claude/plugins` before and after each of the seven batches changed only the running Codex daemon's files, a rotated `~/.codex/tmp/arg0` directory in batch 3 that no batch-3 call explains, and `.in_use` markers written by running Claude Code sessions; the real Copilot cache held no file newer than each batch's start.
- No arm opened a model session or a Copilot session; every `codex debug prompt-input` ran on a stand-in plugin whose scripts had been stubbed or removed.
- Rulings made during adjudication, each of which would have discarded a run if decided the other way:
  - a `cd` into the run directory itself (s2-r3, s6-r1, s6-r3, s1-r1 to s1-r4, s4-r3) is allowed, because every read there is allowed and every write in those calls landed under WORKDIR;
  - the symlinks Codex creates in a throwaway `CODEX_HOME/tmp/arg0` to its own installed binary (s3-r1, s4-r8) are not an escape, because they lead to read-only program files, not a tool home;
  - s4-r9's fetches of Codex's plugin documentation page and the Agent Plugins specification's Markdown are read-only documentation, which the preamble allows; plan 2b's s4-r8 discard concerned fetching program source files.
