## Final report

I added `lint-kit` to both marketplace catalogs, the Claude Code one and the Codex one. The changes are not committed.

**Why both catalogs:** the README lists only two exceptions. `claude-hooks` is for Claude Code only and `codex-helper` is for Codex only. `alpha-notes` and `branch-tidy` have no exception and appear in both. `lint-kit` has no exception either, so I listed it in both.

**What changed:**
- `$RUN/s2/.claude-plugin/marketplace.json`: new entry with `"source": "./plugins/lint-kit"` and `"description": "lint-kit"`. The description is just the plugin's name because every existing entry does the same.
- `$RUN/s2/.agents/plugins/marketplace.json`: new entry with a local source path of `./plugins/lint-kit`, `AVAILABLE` / `ON_INSTALL` policy, and the `Developer Tools` category, copied from the other entries.
- In both files the new entry goes at the end, which keeps the lists in alphabetical order. The README needs no new note because `lint-kit` isn't limited to one platform.

**Checks run:**
- Both files still parse as JSON, and every `source` path in each catalog points to a directory that exists.
- `claude plugin validate .` passed on the Claude marketplace file, and `claude plugin validate plugins/lint-kit` passed on the plugin. Both ran with a throwaway `CLAUDE_CONFIG_DIR` under `.tool-homes/`, which I deleted afterwards.
- I did not check the Codex catalog with a Codex tool, because I don't know of a validation command for it. The only check on that file is that the new entry is built the same way as the existing ones.

**Open question:** `lint-kit` has only a `.claude-plugin/plugin.json`, with no `.codex-plugin` manifest. `alpha-notes` and `branch-tidy` are set up the same way and are already in the Codex catalog, so I followed that pattern. I haven't confirmed that Codex loads a plugin that has only the Claude-style manifest.
