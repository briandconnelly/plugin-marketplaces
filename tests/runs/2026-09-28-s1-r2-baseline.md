## Final report

The repo is now a marketplace called `acme-agent-tools` that lists both plugins for Claude Code and for Codex. One thing isn't working: in Codex, `weather-mcp` installs but its MCP server won't start. You can't fix that from this repo; it needs a change in weather-mcp itself (details below).

**What I did** (nothing committed or pushed)
- **Claude Code catalog:** `$RUN/repo/.claude-plugin/marketplace.json`. `hello-tools` points at `./plugins/hello-tools`. `weather-mcp` is fetched from GitHub repo `acme/weather-mcp` with `ref: v1.3.0` and `sha: bdee23e46e072243455f1ba83ce9d8e2d7584e0a`.
- **Codex catalog:** `$RUN/repo/.agents/plugins/marketplace.json`. Same two plugins in Codex's format: a local path for `hello-tools`, and `https://github.com/acme/weather-mcp.git` with the same ref and sha for `weather-mcp`.
- **README:** `$RUN/repo/README.md` now has install commands for both tools, a table of the plugins and where they come from, and the Codex known issue.
- `.tool-homes/` is excluded through `.git/info/exclude`, so it won't be committed.

**Why pin to the commit and not just the tag**
- `v1.3.0` is a lightweight tag, so it can be moved. The commit is what locks the release.
- Newer `v1.4.0` adds code that sends the city and the user's `$USER` to `https://metrics.acme.example/collect` on every forecast. Pinning to the commit keeps that out, and it's worth reviewing before you ship 1.4.0.

**How I checked it**
Both tools ran with throwaway config under `.tool-homes/`. I didn't contact GitHub or send any prompt to a model. For `weather-mcp` installs I used scratch copies of each catalog that point at the local mirror with the same ref and sha.

- **Validation:** `claude plugin validate` passed on the repo and on `plugins/hello-tools`. As a control, a copy with a `..` path failed, so the validator does catch errors.
- **Claude Code:**
  - Adding the marketplace and installing `hello-tools` worked; it shows version 0.3.0, enabled, with 1 skill and the `hello` MCP server.
  - `weather-mcp` installed as version 1.3.0, and the installed `server.py` is the 1.3.0 file.
  - Control: with `ref: v1.4.0` and no sha, the same install gave 1.4.0, so the pin really decides the version.
- **Codex 0.157.1:**
  - `codex plugin marketplace add` found `.agents/plugins/marketplace.json`, and `codex plugin list` shows both plugins with the correct GitHub source, ref and sha.
  - `hello-tools` installed as 0.3.0. `weather-mcp` installed as 1.3.0.
- **Server start-up:** I put stand-in `python3` and `uvx` programs first on PATH that record the arguments they're started with. Then I had each tool start the plugins' servers (`claude mcp list`, and Codex's app-server listing its MCP servers).
  - Claude Code starts `weather` with the real installed path to `server.py`.
  - Codex starts `hello` correctly but gives `weather` the literal text `${CLAUDE_PLUGIN_ROOT}/server.py`. It doesn't fill in the variable, so the real server would fail.

**The Codex problem and its fix**
- The cause is weather-mcp v1.3.0's own `.mcp.json`, which refers to the plugin folder in a way only Claude Code understands. Neither catalog can override a plugin's server settings.
- Fix: weather-mcp should add a root `plugin.json` and a `mcp.json` in Codex's portable format that use `${PLUGIN_ROOT}/server.py`. I tried this in a scratch copy and Codex then started the server with the correct path. I haven't checked that change against Claude Code.
- Decision for you: I left `weather-mcp` in the Codex catalog, flagged in the README. The alternatives are to drop it from Codex until an upstream release has that fix, or to copy v1.3.0 into this repo with the change.

**Other notes**
- The same sha is written in both catalogs. When you ship a new release, update both together; nothing checks that they match.
- The mirror's `server.py` at v1.3.0 is only a function, not a full MCP server. Even with correct paths I'd expect a real start-up to fail its first handshake; I only checked the paths and arguments.
- Not tested: fetching from real GitHub, and actually running the skills or tools in a session.

 # acme-agent-tools
 
 Plugins our team uses with coding agents.
+
+## Install
+
+This repo is a plugin marketplace named `acme-agent-tools` for both Claude Code and Codex.
+
+Claude Code reads `.claude-plugin/marketplace.json`:
+
+```bash
+claude plugin marketplace add acme/<this-repo>
+claude plugin install hello-tools@acme-agent-tools
+claude plugin install weather-mcp@acme-agent-tools
+```
+
+Codex reads `.agents/plugins/marketplace.json`:
+
+```bash
+codex plugin marketplace add acme/<this-repo>
+codex plugin add hello-tools@acme-agent-tools
+codex plugin add weather-mcp@acme-agent-tools
+```
+
+## Plugins
+
+| Plugin | Source |
