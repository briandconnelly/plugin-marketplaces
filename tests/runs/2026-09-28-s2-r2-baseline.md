## Final report

I added `lint-kit` to both of the repo's marketplace catalogs, and both tools accept it. There is one thing for you to decide: the plugin reports a different version in each tool.

**What changed** (not committed):
- `$RUN/repo/.claude-plugin/marketplace.json` (Claude Code): new entry `{"name": "lint-kit", "source": "./plugins/lint-kit", "description": "lint-kit"}`. The description just repeats the name, like the other entries in this file.
- `$RUN/repo/.agents/plugins/marketplace.json` (Codex): new entry with a local source path of `./plugins/lint-kit`. The policy (`AVAILABLE` / `ON_INSTALL`) and category (`Developer Tools`) are copied from the other entries.

I listed it in both catalogs because the README only names two exceptions: `claude-hooks` is Claude-only and `codex-helper` is Codex-only. `lint-kit` is a general plugin like `alpha-notes` and `branch-tidy`, which are in both. No README change was needed.

**Checks run.** The Claude and Codex command-line tools used throwaway config directories under `.tool-homes/`, which I deleted afterwards. No prompts were sent to any model.
- `claude plugin validate` passed for the Claude catalog and for `plugins/lint-kit`. To make sure the check can actually fail, I ran it on a copy with a broken `lint-kit` entry, and it reported `plugins.3.source: Invalid input`.
- In Codex, I added the repo as a local marketplace, and `codex plugin list` shows `lint-kit@acme-tools`. `codex plugin add lint-kit@acme-tools` installed it successfully.

**Version mismatch for you to resolve.** `plugins/lint-kit` has two manifests that disagree:
- `plugins/lint-kit/.claude-plugin/plugin.json` says `1.0.0`. This is the file Claude Code validates.
- `plugins/lint-kit/plugin.json` says `1.1.0`. Codex installed the plugin as `1.1.0` from this file.

So Claude Code users and Codex users will see different versions of the same plugin. I didn't change either one because I can't tell which is correct. Once you tell me, the other manifest should be updated to match.
